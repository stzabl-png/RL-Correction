### L5-18 self_collision 三处来源, 三个说法 (2026-08-29)
- 追一个字段追出三个来源:
  ```
  采集器默认值        False   ← getattr(..., False), 蒙对了但不是读来的
  correction_env_cfg  True    ← 写了, 但对本任务 articulation **未生效**
  USD authored 属性   False   ← PhysX 真正读的 (/World/envs/env_0/Robot/root_joint)
  ```
- ★两条教训:
  ① **值对了 ≠ 记录可信**。原来那个 False 恰好等于真值, 但它来自默认值而非读取 ——
     如果 cfg 真的生效了, 它就会静默交出一个错值。**蒙对比错更危险, 因为不会被发现。**
  ② **"配置写了"≠"生效了"**。用 cfg 去质疑运行时是不够的, 真值只能从运行时/USD 取。

  并新增 `*_source` 字段。**来源与值同等重要** —— 没有来源就无法区分
  "读到了 False" 和 "默认成了 False"。
  ⟹ 规矩: 交付物里的物理量, 一律带 `_source`。

#### 31.13 ★straight 臂 (POUR_ARM_FREE) + 六条线发射 (2026-08-30 深夜)

**用户裁定(读法B)**: straight = "物体轨迹直接当目标, **不解算 IK 变成臂参考**"。

★**为什么"去掉 IK"必然牵扯到臂**: 动作是 `q_tgt = ff + cum_res`, 而 `ff` **必须**是

#### 32.12 `noise` 臂 —— 噪声只注朝向, 且按每个物体的实测残差定档

出厂检查比的成了"加噪 vs 加噪+平滑"(量的是平滑器清掉多少, 不是任务退化多少),

#### 32.16 ★★根因: 「红档不判朝向」同时造成假 G3 **和** placed 恒 0 (2026-08-31 晨)
