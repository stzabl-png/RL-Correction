# 先抓后飞·无混合 —— 第一条完整合格配方的成功经验总结

> 2026-08-03 22:40。期中检验(8.5M 步存档):**端到端确定性 99.95%**(10877/10882)/
> 训练分布对照 99.97%,成功中位 79 步,到达仅 41 步(单次直达),起点=用户设计的
> 双臂对称站姿。用户已验收录像。复现确认(seed 7/21 从零)进行中,判据见台账 §2.18。

## 一、配方本体

```bash
SHARPA_WANDB=0 PYTHONPATH=. python -u -m tasks.pregrasp.train --headless \
  --clip Grasp3 --num_envs 1024 \
  --prior_npz tasks/pregrasp/priors/Grasp3_candidates/8_5.npz --prior_yaw 215 \
  --approach --stance_prefix 60 --kl_threshold 0.02 \
  --grasp_first --gf_target 0.8 --max_agent_steps 40000000
```

四个关键组件(缺一即回到历史失败模式):
1. **站姿前缀** `--stance_prefix 60`:参考轨迹前拼"对称站姿→人手轨迹起点"插值,任务从
   正确起点出发(PLAN D2)
2. **先抓后飞门控** `--grasp_first`:阶段A 100% 回合纯练抓取,慢EMA≥0.8 毕业才放行接近
3. **抖动起点池**(门控自带):阶段A 起点带 ±3cm/±15° 随机偏移(=课程全程合法到达误差的
   包络),抓取天生容错,交接不断裂
4. **kl 0.02**:trust region 压小,必要非充分

**不需要**的东西(都试过并证伪):姿态混合、锥形信任管、更小的 kl(0.01)、课程提速、
组3 PPO 超参、人为抖动直接起步(混训语境)。

## 二、三个被数据确认的机制,也是三次转折

### 1. 训练不稳定的病根 = "起步竞速",解法 = 顺序化
两个起步分支共享一张网,前 3M 步是竞速窗口:抓取先巩固则活(B/S1),没巩固就被接近段
失败梯度冲掉(N1/N2/N3/A,kl 0.05/0.02/0.01 三档都救不了)。9 条混训 run 幸存率 2/6+。
**把竞速改成顺序(先抓后飞),运气变制度**——本配方毕业后 2.4M 步端到端即达 0.45,
6M 步 0.98,是 B(40M)速度的约 6 倍,且无一次技能崩塌。

### 2. 交接断裂的病根 = 抓取不识偏差,解法 = 抖动起点池(用户设计)
O1 铁证:到位率 76%(1.7cm/3.1° 精度)但端到端 0——只会从标准起点抓,不会纠正到达
偏差。P0.0 容差曲线早有预兆(3cm 起点→42.9%)。抖动池让抓取在"到达误差分布"上毕业,
交接自带容错。救援臂反向验证:O1 的技能+抖动池,容错抓取 0.50→0.80 补课可行。

### 3. "双接近"的病根 = 参考固有形状+折扣贪心,解法 = 意外地被 1+2 顺带治好
探针曾确诊 S1 的绕路来自参考摆出段(转向走廊)+势函数早收益。原计划用姿态混合/锥管
修行为——**全部没必要**:抓取先巩固且带容错后,策略自己学出 41 步直飞路线,不再依赖
参考的转向走廊,双接近自然消失。复杂机制被正确的训练顺序取代。

## 三、工程教训(每条都付过学费)

- **口径与工具先于算法**:录像暴露起点错误(人手轨迹起点≠设计站姿)、eval/record 曾
  根本不开 approach——先把"测什么"搞对,再谈"训得好不好"
- **数字要配行为验收**:99% 的 TB 曲线下面可能藏着绕路/两次接近;逐步探针(diag_trace)
  和慢放录像是判读的最后一关
- **带中心要跟起步走**:偏差带钉死在 prior 位形,任何偏离起步(抖动池)第一步就被钳制
  猛甩——同一失败模式在切换路径修过,reset 路径漏掉(已修);tol_curve 的历史数据被
  同一 artifact 污染,是悲观下界
- **进度条的数学要和判据配平**:毕业线 0.9 与技能平台 0.9 打平=永不触发;慢 EMA(0.995)
  的半衰期会让进度条比技能晚数百万步——一次性事件用快 EMA(0.95)
- **失败臂的价值在归因**:C1/OC1/O1/姿态混合各自证伪了一条路,没有它们就说不清冠军
  赢在哪个组件上;单变量 + 预注册判据是整个循环的引擎
- **续训是廉价的实验杠杆**:改毕业参数/补课都从 ckpt 续训,技能不丢,墙钟损失半小时级
