## 0. 任务定义与三层决策

**`task = pick_lift`**：机器人从**默认站姿**出发 → 接近物体 → 形成稳定抓握 →
微抬升 1cm 物理验证。PreGrasp **不再是任务名**，它是 `pick_lift` 内部的一个阶段。

任务级 / 物体级 / 物体×任务级三层必须分开，否则数据成本按乘法爆炸：

### 2.1 覆盖：每物体 3~4 个 run 就够（实测）

> 下递归收集到的 `*_grasp.npy` 里，**`init_data/` 的 500 个是未优化的初始种子**，

> （`grasp_data/` + `isaac_succ*/` + `grasp_data_isaac_failed/`）。
> 我第一版把种子也数进去了，得到"505~643 个候选"，**错**。

把**真候选**的 `obj_cpn_w`（5 接触点+法向）解到物体系，最远点选 K 个，
算"所有接触点落在已选候选接触点 2cm 内"的比例（2cm = `arm_dev_max` 的探索半径）：

| 物体 | **真候选** | 质心间距中位 | K=1 | K=2 | **K=3** | **K=4** |
|---|---|---|---|---|---|---|
| pp3 方块 3.7cm | **143** | 1.4 cm | 30% | 82% | **100%** | 100% |
| pp5 小环 5.8cm | **77** | 2.1 cm | 34% | 86% | 93% | **100%** |
| pp1 长条 11.6cm | **5** | 5.6 cm | 40% | 72% | **100%** | 100% |

⟹ **K=3~4 即可覆盖候选池提出的全部抓握区域**。按 GraspPose_5 的实测
（5.8M 步 / 40 min / 4080S），8 卡并行 ⟹ **一个物体约 1 小时墙钟**。

🔴 **"覆盖候选池" ≠ "覆盖物体表面"**：pp1 全部只有 **5 个**真候选，K=4 覆盖的是
这 5 个提出的那点区域，长条其余表面永远 unknown。**候选池的稀疏本身就是数据瓶颈**
（这也是 §8 R1 停止规则要解决的问题）。

选这 K 个的规则：`Gate0 ∩ Gate1 ∩ H3` 存活者里，**按接触质心做最远点采样**
（不是按 Q\* 排序取前 K —— 那会全挤在同一面）。其中 **2/3 取 Gate2 通过者，1/3 取
Gate2 判死者**（D5）。

### 2.2 记录规格

每物体一张表，跨 run 累加：

```
score_table[obj][task][template]:
    s (P,) uint32     成功计数（力加权）
    n (P,) float32    访问计数（力加权 + 折扣）
读数 q = (s+1)/(n+2)          n < n_min ⟹ unknown（**不能写 0**）
```

| 规则 | 做法 | 依据 |
|---|---|---|
| **何时计** | 只在 **verify 斜坡到顶那一刻**取快照 | 微抬升是物理干预，撑不住的接触点自动掉出接触集 = 廉价因果筛子 |
| **计哪些点** | 该刻 `pads_on` 的垫 → 各自最近表面点索引（`_pad_dist_normal` 里已算出 `idx`，现在被丢掉了） | 零新增计算 |
| **权重** | 该垫在该刻的**力占比** `mag_i / Σmag` | 分开"承重的点"和"陪站的点" |
| **正/负** | 回合最终成功 → `s += w, n += w`；失败 → 只 `n += w` | |
| **折扣** | 每 epoch 全表 `s, n *= 0.999` | 早期弱策略的标签不会永久压住后期数据 |
| **粒度** | 索引用 2048 点；**2048 点的 cdist 只对 verify 中的 env 算** | 奖励侧 512 点不动；全量 3072env×5×2048 太贵 |

两个让"多 run 可合并"的性质（已核）：
1. **yaw 钉死后所有 run 共享同一物体摆放** ⟹ 表面点索引直接对齐，(s,n) 逐点相加。
2. **FPS 采样嵌套**：`frames.sample_surface_points(seed=0)` 是贪心 FPS，只有第一个点用 rng
   ⟹ n=512 的 512 点 = n=2048 的前 512 点。**现在按 512 记，以后升 2048 不用重跑。**

**支持域的诚实说明**：表的有效区域 = 候选池接触区 ∪ ±2cm。候选池从没提议过的表面
永远 unknown，模型在那里是**外推**。这条必须写进产物 meta。

## 3. 接近 + 抓取（一次训完，不分段）

### 3.1 动作：前馈参考**增量**，不是位置

```python
q_cmd = q_cmd + (q_base − q_base_prev) + arm_res      # q_base = q_ref[t]
```

这是基类 `dexmate_env.py:384-392` 的 `accumulate_action` 模式，注释已写明教训：
"只累积不给前馈 ⟹ 零动作时手臂冻在起点（实测抬升 0.15cm）"。

| 约束 | 为什么满足 |
|---|---|
| 不平移人手轨迹 | 公式里只出现 `q_ref[t] − q_ref[t−1]`（**差分**），绝对位置不进公式 |
| 零动作 = 可用解 | 零动作 = 逐帧复现人手的速度剖面和曲率（repo 两次成功都靠这条性质） |
| 对 gs 标注误差不敏感 | gs 只决定权重/管壁的时间表，**不决定任何位置目标**；差 ±5 帧 = 曲线平移 0.25s，无位置跳变 |

**前馈只在 `t < gs`**；`t ≥ gs` 后 `q_base` 冻结在 `q_ref[gs]`，剩下的缺口由残差 + 势场合上。

### 3.2 轨迹保真：只剩**软**约束，且是"增量"口径

⚠ **2026-08-02 结构性修订**（方案 C）。原设计有"管壁（硬）+ 模仿罚（软）+ 对齐势（终点）"三层，
其中管壁约束的是"手离参考轨迹的**绝对位置**多远"。但 §7.7 实测：人手轨迹被系统性平移了
**14~16cm**（相机↔手标定偏差，四条 clip 方向与量级一致）。

⟹ **任何基于绝对位置的约束都是有害的**：套一个 5cm 管壁，手永远到不了物体。管壁、
`R_hi`、`φ_open`、`H3` 全部删除。

改用**增量口径**。因为动作是 `q_cmd += 参考增量 + 残差`：

```
手这步走的 − 参考这步走的  ≡  残差

r_imit = − w_imit(φ) · min(‖本步残差‖_末端 , cap_imit)
```

含义：**早期少用残差 = 照着人的走法走；后期残差免费 = 随便拐去 GraspPose。**
一个项、一条衰减曲线，与那个 16cm 常数偏移**完全无关** —— 这正是数据允许我们相信的部分
（形状与速度剖面可信，绝对位置不可信）。

**代价（必须承认）**：轨迹保真从"结构保证"降级为"可被策略权衡的奖励项"。策略可能学出
不太像人的路。这是保留 XY 摆放约定 + 数据带 16cm 误差的必然结果。
诊断信号 `diag/res_used_cm`（接近段累计残差用量）：一上来就顶满 ⟹ 模仿罚太轻。

### 3.3 对齐势函数

```
d_pos = ‖_anchor_w() − _target_w()‖            [m]  （合拢中心 → 接触质心，已在 obs 里）
d_rot = angle(wrist_quat_w, q_grasp_w)          [rad]
Φ     = −( d_pos + λ_rot · d_rot )              [m]
r_align = w_align · clip(Φ(t) − Φ(t−1), ±cap_align)
```

- `λ_rot = 0.174 m/rad` —— **P0.0 实测**（5° 姿态误差 ≡ 1.52cm 位置误差），是纯运动学
  力臂（≈0.08）的 2 倍。机理：平移让五个垫**整体**平移，旋转让每个垫的**接近方向**各自改变。
- 用**合拢中心**不是腕原点：要到位的是它。

🔴 **`w_align` 必须恒定，不能随相位变。** 势函数整形安全的前提是电报级数
`Σ(Φ_t − Φ_{t−1}) = Φ_end − Φ_start`（与路径无关）。权重一旦随时间变就不再 telescoping，
策略可以**早期 w 小时后退、晚期 w 大时前进**无限刷分。
"越近 GraspPose 权重越高"是**比值** —— 让 `w_imit(φ)` 衰减即可达到，且无洞。

### 3.3b 残差权限必须"远松近紧"

方案 C 下手要**自己走完 16cm**：

| | |
|---|---|
| 抓取段每步残差上限 | ≈ 5mm/步（`arm_residual_max × arm_step_scale=0.25`）|
| 接近段放大（`dyn_arm_far = 3.0`，基类已有） | ≈ 15mm/步 |
| 走完 16cm 需要 | ≈ 11 步 |
| 最短的接近窗口（Grasp3） | **32 步** ⟹ 3 倍余量 ✅ |

不开距离缩放就是二选一：要么走不到，要么接触前手抖太大（`MANUAL.md §6.1` 那条
"残差界 × sigma = 抓握杀手"）。机制基类现成（`dyn_res` / `dyn_arm_far`），任务层接上即可。

### 3.4 相位调度 φ 与切换

```
φ = clamp(t / gs, 0, 1)          t = 参考帧号（每步 +1，与机器人表现无关）
w_imit(φ) = w_imit0 · (1 − φ)²
```

**φ 必须用参考时钟，不能用"到物体的距离"**：距离是策略能操纵的量（可以靠近来关掉
模仿罚），时钟不是。φ 已在 obs 里（`phase_prog`）——权重随时间变而策略看不到时间，
MDP 从策略视角是非平稳的，学不动。

- 切换 GRASP：`d_pos < ε_pos` 且 `d_rot < ε_rot` 且腕速 < v_max，**带滞回**
- **没有强制切换**（上一版的 `gs+margin` 强切已废）：到不了就 episode timeout，
  是干净的负样本，不会被"直线拽进物体"
- 合拢斜坡按相位门控：`ref *= (phase == GRASP)`，接近段手必须张开
- `c0` 随机化只对"起步即在 GRASP 相位"的回合生效

### 3.5 课程 = RSI，不是分段

`correction_env_cfg.py:81-90` 已有：`rsi_prob=0.8` / `rsi_mode="linear"|"success"` /
`rsi_warmup_steps` / `rsi_decay_steps`（退火到 0）。回合从参考时钟的随机帧起步，
逐步退回起点。**一个旋钮、任务无关**，不需要人去定义"第一段练什么"。
`closure_init_max=0.9` 本来就是同一思想作用在手指轴上。

复位钩子已就位：`env.arm_start_pool`（`(K,7)` 张量，复位时随机抽一行）。

- 判读：`success_rate` 按 `rsi_start` **分桶**记（从头 vs 从中段）⟹ 单 run 内分辨
  "接近坏了"还是"抓取坏了"，不牺牲可诊断性
- **免费回归验收**：`rsi_start = gs` 那一桶就是今天的任务，成功率必须仍 ~100%。
  掉了 ⟹ 改坏了底层，与接近段无关

### 4.1 ~~管壁半径~~ —— **已删除**（2026-08-02，方案 C）

原来这里是 `R_hi = G/0.7 + 3.5cm` 一套派生公式。方案 C 下人手轨迹不再平移，

### 4.2 奖励量级（由现有奖励盘子倒推）

现成锚点：`r_candidate=3.0` / `r_success=40.0` / `w_hold=0.3`。
**接近段总价值必须明显低于"形成候选抓取"**，否则策略把预算花在走路上。

| 参数 | 初值 | 推导 |
|---|---|---|
| `w_align` | **6.0**（恒定） | ΔΦ ≈ 0.27~0.48m（姿态项占大头：`0.174 × 1.05~2.25 rad`）⟹ 全程 ≈1.6~2.9 < `r_candidate` 3.0 ≪ `r_success` 40 |
| `cap_align` | 0.02 m/步 | 接近速度 ≈1cm/步 的 2 倍，只挡物理尖峰 |
| `λ_rot` | **0.174 m/rad** | **P0.0 实测**（5° ≡ 1.52cm），纯运动学力臂的 2 倍 |
| `w_imit0` | **20.0**（作用在**残差用量**上，单位 分/(m·步)） | 典型残差 0.5~1cm/步 ⟹ 0.10~0.20 分/步，与 align 单步上限 0.12 同量级 |
| `cap_imit` | **0.02 m/步** | 惩罚单步上界（台账铁律）；等于残差的物理上限 |
| `imit_decay_p` | 2（`(1−φ)²`） | 早期主导、gs 处归零 |
| `dyn_arm_far` | 3.0（基类已有） | 远处 15mm/步 ⟹ 11 步走完 16cm，最短窗口 32 步，3 倍余量 |
| `ε_pos` / `ε_rot` | **1.04cm / 2.18°** | **P0.0 实测（90% 档）** |
| `approach_budget` | `gs + 20` 步 | 到不了就 timeout（无强制切换）|

**抄近路的不等式**（"多像人"的唯一旋钮）：

```
早期用满残差的代价 = w_imit0 · cap_imit = 20.0 × 0.02 = 0.40 分/步
抄近路换来的对齐收益 ≤ w_align · cap_align =  6.0 × 0.02 = 0.12 分/步
        0.40 > 0.12  ⟹  早期猛用残差直冲是亏的
```

φ→1 时 `w_imit` 归零，不等式翻转 —— **故意的**：那时人手姿势与 GraspPose 差 33~129°，
必须让 GraspPose 赢。

### 7.2 affordance 热图的实测（为什么它只能当粗筛）

20 个物体的热图选择性：**obj_00 / obj_01 / obj_14 没有任何点 heat>0.5**；
obj_05 有 47% >0.5（过于弥散）；有峰且集中的只有 obj_03/07/10/16/19。

用它给 6 个已知成败的候选排序，**方向是反的**：

| 候选 | 已知结果 | 接触点 heat 均值 | 物体内百分位 |
|---|---|---|---|
| Grasp5 prior | ✅ 100% | 0.436 | 50% |
| Grasp3 prior | ✅ 100% | 0.078 | **39%** |
| pp1_21_7 | ❌ Gate2 判死 | 0.184 | **83%（最高）** |
| pp1_32_2 | ❌ 判死 | 0.094 | 56% |
| Grasp1 / 44_6 | ❌ 回避塌缩 | 0.086 | 52% |
| pp1_15_4 | ❌ Gate1 判死 | 0.052 | 36% |

原因是结构性的：affordance 学的是**人手接触区**（Stage A 目标 = "is this a hand-contact
region"），人多是两三指捏；Dexonomy 出的是五指 `fingertip_mid`。两者本就不该重合。
⟹ affordance **不作前置过滤器**，只与 Gate1 并列做"省 Isaac 时间"的粗筛。

技术前提已核：prior `contact_pos` / affordance `points_raw` / 重建 mesh **三者同系**，
bbox 逐位吻合，接触点到最近 affordance 点中位距离 0.20~0.41cm ⟹ 打分是**无需坐标变换**的最近邻查表。

### 7.3 交互标注 `gs` 无法独立验证（为什么设计必须对它不敏感）

`load_replay.py:113` 有一个与标注无关的几何判据（MANO 指尖进入物体半径+3cm）。拿它对标注：

| clip | 标注 gs | 几何交互段 | 差 |
|---|---|---|---|
| Grasp5 / Grasp3 / Grasp2 | 64 / 32 / 45 | **(0,−1) 空** | — |
| Grasp0 | 47 | (0, 28) | −47 帧 |
| Grasp1 | 55 | (68, 73) | +13 帧 |

三条 clip 上"手指从来没靠近过物体"——不是标注错，是**几何判据本身不可信**
（`MANUAL.md §7.3`：人手重建腕位误差约 20cm）。⟹ **现在没有任何独立手段验证 gs**，
设计必须对 gs 误差不敏感（§3.1 第三行）。

推论：人手轨迹里可信的**不是绝对位置，是形状与速度剖面**
（实测腕速峰值 21~44 cm/s，到 gs 附近降到 4~13 cm/s，一条减速接近曲线）。

> ⚠ 前一版对照曾显示"差 0 帧"，那是循环论证——`replay_grasp.py:303` 把
> `interaction_seg` 直接覆盖成了标注值。已作废。

### 7.4 P0.0 到位误差容差曲线（2026-08-01 实测）

`tasks/pregrasp/tol_curve.py`，`GraspPose_5` 的 100% 权重，正式口径 A（c0=0，gentle=1.0，
确定性 mu），1024 env × 300 步/档，每档 2200~5500 回合。产物 `data/tol_curve_Grasp5.json`。

| 位置误差 | 姿态误差 | 成功率 | 主失败模式 |
|---|---|---|---|
| 0 | 0 | **99.66%** | — |
| 0.5 cm | 0 | 96.57% | timeout |
| 1.0 cm | 0 | 90.92% | timeout |
| 2.0 cm | 0 | 65.01% | timeout |
| 3.0 cm | 0 | 42.85% | timeout |
| 0 | 5° | 77.50% | timeout |
| 0 | 10° | 59.15% | timeout |
| 0 | 15° | 45.27% | timeout |
| 1.0 cm | 5° | 77.00% | timeout |
| 2.0 cm | 10° | 28.66% | timeout |

**读出来的三个数**：

| 量 | 值 | 用途 |
|---|---|---|
| `ε_pos` | 0.64cm(95%) / **1.04cm(90%)** / 1.42cm(80%) | 相位切换阈值 |
| `ε_rot` | 1.05°(95%) / **2.18°(90%)** / 4.44°(80%) | 相位切换阈值 |
| `λ_rot` | **0.174 m/rad**（5°≡1.52cm）；10°≡2.26cm，15°≡2.89cm ⟹ 大角度饱和到 0.11 | 对齐势函数的姿态权重 |

**三条判读**：

1. **姿态误差比位置误差贵一倍**。纯运动学力臂预测 λ_rot≈0.08，实测 0.17。
   机理：平移让五个垫**整体**平移，旋转让每个垫的**接近方向**各自改变。
2. **失败几乎全是 `timeout`**（fell/thrown 各只有个位数）。带到位误差时，策略不是
   "抓住又掉了"，而是**从头就凑不齐 4 垫同时接触**。这与 `pads_now` 是候选硬门槛一致。
3. **组合误差不可加**：(1cm,5°) 实测 77.0% 远好于可加性预测 53.5%；但 (2cm,10°)
   实测 28.7% 又差于预测 42.9%。**没有简单合成律，别外推**；小角度区用上表直接查。

⚠ **两条必须记住的限制**：

- **这是下界，不是天花板。** 这条曲线量的是"把误差**交给一个从没见过误差**的策略"
  会怎样（该策略是从精确 prior 位姿起步训的）。接近+抓取一次训完时，抓取相位会看到
  真实的到达分布并适应，容差**应当明显变宽**。所以 `ε` 取 90% 点是**保守起点**，
  P3 训完要用同一脚本重测一次，看曲线是否右移 —— **这就是 P3 的一个验收指标**。
- **起始位形池有方向偏置**：IK 接受率只有 29~60%（`iters=80` + 固定种子），
  能解出来的扰动方向不是各向同性的。绝对数值可能偏乐观，但各档协议一致，**相对形状可信**。

### 7.7 手↔物体 XY 关系的系统误差（2026-08-02 实测，方案 C 的依据）

关掉 `pregrasp_align`（= 纯相机锚定，XY 完全保留重建原样），量"标注说开始接触"的那一帧 gs：

| clip | 合拢中心→物体原点 | **其中水平** | 最近指尖→物体表面 |
|---|---|---|---|
| Grasp3 | 16.6cm | **15.7cm** | 11.5cm |
| Grasp5 | 16.6cm | **14.8cm** | 13.1cm |
| Grasp1 | 15.9cm | **14.0cm** | 12.3cm |
| Grasp2 | 15.3cm | **14.0cm** | 12.4cm |

**四条 clip 方向一致、量级一致 ⟹ 系统误差，不是噪声。** 腕→指尖最大伸展只有 17.3cm，
所以"忠实保留重建的手↔物 XY 关系"= 手永远够不着物体。

误差源大概率是"人头相机 → 机器人 ZED"的标定映射。**真正的修法在上游**
（`Reconstruct_and_Retarget` 的相机↔手标定）；修好后人手轨迹才是可信的**空间**先验，
现在它只是可信的**形状/速度**先验。

`pregrasp_align`（曾默认开）就是盖这个洞的补丁：额外 smoothstep 平移整条腕轨迹到
"affordance 上方 8cm"（Grasp3 实测 `[-5.53,-10.55,-6.72]cm`）。它是"先验证能不能学会抓"
阶段的脚手架，**有了 GraspPose 之后已无必要**（用户 2026-08-02 定），且它破坏 XY 摆放约定。
