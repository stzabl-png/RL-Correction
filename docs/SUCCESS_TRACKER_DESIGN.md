## 0. 一句话

**Success Tracker 不是"一条成功判据",而是一套"判据的质检系统"**:
它同时维护一个**便宜的 sim 内代理**(进奖励、逐步可算)和一个**昂贵的权威判官**(抽样),
并**持续测量两者的一致率** —— 一致率掉下去的那一刻,就是策略开始刷分、或判据开始漂移的那一刻。

理由是本项目的实测史:仪表出过太多次事,而且每次都是靠**用户看录像**才发现的。

| 事故 | 表现 | 根因 |
|---|---|---|
| 单指蹭转刷分(§2.21 X2 预警) | 成功率涨,录像里盖没被真捏住 | 判据只看转角,不看"谁在转" |
| 歪着抓(§2.20-姿态) | 40/40 成功回合瓶身倾角 17~19° | 成功定义里**没有姿态项** |
| 仪表读到 0(同上) | eval 在 `_reset_idx` 之后读 `tilt_max`,全是 0 | **读取时机**错 |
| TB 成功率高估 | 同 ckpt TB 26.7% vs 正式口径 0.00% | **口径混用**(c0 脚手架 + 长度偏置) |

⟹ 设计的第一原则:**判据本身也要被证伪、被质检、被版本化。**

## 1. 三层判据(成本与权威性递增)

| 层 | 谁在算 | 频率 | 用途 | 倒水任务的具体内容 |
|---|---|---|---|---|
| **L0 逐步谓词** | sim 内,张量化 | 每步 × 每 env | 进**奖励与终止** | 相对构型进容差、保持计数、脱手、打翻 |
| **L1 回合判定** | sim 内,确定性评测 | 每回合 | **正式成功率口径** | L0 保持达标 ∧ 收尾(若演示有 place 段) |
| **L2 权威判定** | 抽样,贵 | 每 ckpt 抽数十~百回合 | **质检 L0/L1** + 入库把关 | L2-phys / L2-sem(下节) |

**L2 有两个互相独立的权威**(互为交叉验证,不共享失败模式):

- **L2-phys 物理内生**:**评测期**在源容器内放少量标记内容物(粒子/小刚体),
  量 `transfer_ratio = 进入目标容器的量 / 总量`,并分出 `spilled`(落到别处)与 `retained`(没倒出来)。
  **训练期关闭** ⟹ 训练零成本,评测有物理真值。
  任务知识住在**数据**(哪个是源容器由 VLM/LLM 层给;数据集自带 `llm_verbs:['pour']`),
  不住在代码;对一切"转移类"任务通用。
- **L2-sem 语义**:渲染 rollout 交 VLM 与原视频对拍。
  ⚠ 时间分辨率约束(实测,见 `POUR_TRAINING_DESIGN.md` §4.3):我们的 VLM 对 pour/17 只看到
  **≈18 张画面、间隔 ≈0.26s** ⟹ **采样预算必须集中到驻留段**,不要均匀看全程;
  实测一致率 **92.6%** ⟹ 当判官够用,**当逐步训练信号是毒药**。

**为什么要两个权威**:L2-phys 精确但依赖 sim 建模(粒子参数、容器内腔重建);
L2-sem 抓语义但有 ~7% 错判。二者同时否决 = 铁证;二者打架 = 值得人看的样本。

## 2. Tracker 的核心职责:一致性质检

每个 ckpt 评测后,对被抽样的回合算一张混淆矩阵:

```
                     L2 权威判定
                   通过        否决
L1 代理   通过   ✅ 真成功   ⛔ **刷分**(proxy 被钻空子)
          否决   ⚠ 判据过严   ✅ 真失败
             (白丢好数据)
```

输出三个数,**随训练进程重算**(策略会漂,漏洞是慢慢长出来的):
`proxy_precision`(代理说成功里有多少真成功)、`proxy_recall`、`agreement`。

**动作规则(写死,不临场判断)**:
- `proxy_precision < 0.9` ⟹ **刷分警报**:自动存档该批"代理通过但权威否决"的回合
  (录像 + 逐步判据向量 + 轨迹 npz),**暂停训练等人裁定**(接现成的 `tasks/pregrasp/auto_stop.py`);
- `proxy_recall < 0.8` ⟹ 判据过严,白丢数据,复查阈值(**先查阈值,不许直接放宽成功定义**);
- 两个权威互相打架率 > 15% ⟹ 权威本身有问题,先修权威再谈成功率。

## 3. 记录规范(把历史事故固化成规则)

1. **复位前快照**:一切极值/累计类指标(最大倾角、最小落点距、保持步数、最大接触力)
   必须在 `_reset_idx` **之前**写入快照缓冲,eval **只读快照**。(§2.20-姿态的原教旨)
2. **存判据向量,不存 bool**:每回合落一行结构化记录(见 §5 schema),
   事后换阈值可**直接重判,不用重跑**。
3. **口径显式化**:每条成功率带 `criterion_id + version + 口径标签`
   (半程/端到端、c0 随机化开关、是否含收尾段)。**不同口径的数禁止出现在同一张表同一列。**
4. **失败必须分类**,不只计数(失败构成是下一轮设计的输入)。

## 4. 倒水任务的判据实例化

**L0 逐步谓词**(全部张量化;目标构型来自 `keyframes.json` 的驻留段,不是手写几何):

| 谓词 | 定义 | 备注 |
|---|---|---|
| `held_src/held_dst` | 各手与各自物体保持接触 ∧ 相对手位姿不漂 | 脱手立即终止 |
| `aligned` | 当前"物体↔物体相对构型"进入演示驻留构型的容差球 | 容差随该段可信度放宽 |
| `holding` | `aligned` **连续**计数 ≥ 驻留段时长 | **必须连续**(防抖一下就刷) |
| `knocked` | 任一物体倾角超限 / 掉桌 | 终止 |
| `timeout` | 超过演示时长 × 系数 | 终止 |

**L1 回合判定** = `holding` 达标 ∧ 未 `knocked` ∧(演示有 place 段时)两物体归位。
**失败模式枚举**(互斥,按最早触发):`no_grasp_src / no_grasp_dst / no_align / hold_too_short /
spilled(仅 L2 可判) / knocked / dropped / timeout`。

**L2-phys** = `transfer_ratio ≥ τ`(τ 由演示语义定,起步 0.5),同时报 `spilled_ratio`。
**L2-sem** = VLM 二选一 + 一句理由,采样帧集中在驻留段。

## 5. 每回合记录 schema(草案)

```json
{ "episode_id": "...", "ckpt": "...", "seed": 42,
  "criterion": {"id":"pour_v1","version":3,"口径":"端到端/c0=0/含收尾"},
  "L0_snapshot": {"hold_steps_max": 41, "align_dist_min_m": 0.021,
                  "tilt_src_max_deg": 87.2, "contact_force_max_N": 6.1},
  "L1": {"success": true, "failure_mode": null},
  "L2": {"phys": {"transfer_ratio": 0.78, "spilled_ratio": 0.05},
         "sem":  {"verdict": true, "reason": "瓶口对准杯口并倾倒", "frames_used": 18}},
  "fidelity": {"keyframe_errors_m": [0.018, 0.024], "order_ok": true, "duration_ratio": 1.15},
  "diversity": {"init_layout": [...], "pads_src": ["thumb","middle","ring"],
                "template_id": "5_Light_Tool", "outcome_bucket": "0.7-0.8"} }
```

**fidelity 的通用定义**(不是逐帧像不像 —— 冠军经验证明路径形状本就被策略弃用):
**关键构型达成误差 + 顺序一致性 + 时长比例**。三项都直接来自 `keyframes.json`,任务无关。

## 6. 入库门(D_verified)与去重

**硬门**:L1 成功 ∧(被抽中时)L2 未否决 ∧ 无异常物理(穿模/瞬移/力超限)。
**软门**:fidelity 三项在阈内。
**分级**:`transfer_ratio` 是连续量 ⟹ 数据带**质量分**入库,而不是二值通过。

**去重五维**(README 既定)对倒水的具体化:几何=两物体初始摆放;接触模式=各手参与指集合;
抓姿=模板 id + 腕相对位姿;轨迹=关键构型序列的 DTW 距离;结果=`transfer_ratio` 分桶。
目的**不是删重复,而是保证覆盖分布** —— 去重前先出覆盖直方图。

## 7. 反刷分清单(倒水特有,机制推理得出)

| 漏洞 | 会怎么刷 | 堵法 |
|---|---|---|
| 只看倾角 | 瓶举高一倾,水去哪不管 | `aligned` 必须含相对位置;L2-phys 兜底 |
| 用"记忆中的杯位" | 撞开杯子后仍按旧位置对准 | 判据只读**实时**位姿,禁用缓存 |
| 抖一下就算 | 单步擦过容差 | `holding` 必须**连续**计数 |
| 倒完把杯扣过来 | 事后动作破坏结果 | L2-phys 在**回合末**结算 |
| 举杯去接瓶口 | —— | **这是合法解,不堵**(人的解法不强加) |

## 8. 与训练回路的接线

- L0 → 奖励/终止(逐步);
- L1 → 正式成功率(确定性评测)、里程碑门控;
- **L2 → 不进逐步回路**,只在 ckpt 边界跑抽样,产出:①质检三数 ②刷分警报(接 auto_stop)
  ③入库把关。
- **判据版本变更 = 一次台账事件**:改判据必须写进 `DESIGN_LOOP.md`,并把旧口径的历史成功率
  标记为"不可比"。

## 10. 工序

1. 定义 L0 谓词表(读 `keyframes.json`,张量化)—— 与 env 改造同批;
2. 记录管道(复位前快照 + 每回合 schema 落盘);
3. L2-phys:评测期粒子开关 + `transfer_ratio` 计算;
4. L2-sem:复用 `vlm_grasp_schema.py` 的调用骨架,改 prompt 与**驻留段密采**;
5. 质检报表(混淆矩阵 + 三数 + 刷分档案)接 `auto_stop`;
6. 入库门 + 覆盖直方图。

**1~2 先做**(训练必需);3~6 在 S3/S4 阶段起训前就位即可。

## 11. 按 pour/17 真实重建实例化(2026-08-14)

### 11.0 新增一层:**L−1 世界体检**(判据之前的判据)

pour/17 的实测教训:杯网格径向偏胖 1.3~1.5×(`POUR_TRAINING_DESIGN.md` §11.3)。
这类**第一层世界构造错误 RL 修不了**,而且会让 L2-phys "过宽接住"虚报成功
⟹ **Tracker 的第一道闸不是判策略,是判世界**:

| 体检项 | 判据(通用,不含任务知识) | pour/17 实测 |
|---|---|---|
| 形状比例 | mask 长宽比 vs mesh 长宽比,偏差 >25% 不通过 | 瓶 3.33/3.31 ✅;**杯 2.01/1.52 ⛔** |
| 绝对尺度 | mask+深度+内参推真实尺寸(已知系统低估 ~11%,用同 take 已知物体标定) | 瓶对 CAD 真值差 4% ✅ |
| 位姿可信度 | `conf_pos/conf_rot` + `manifest_status` | 杯 52/5.5(rot 弃用);瓶 83/50 |
| 支撑一致性 | 静置帧物体底面应贴支撑面 | 待跑 |

**不通过 ⟹ 不许开训**,并记入 take 的 provenance;修法优先级见 §11.3(各向异性重标定 → CAD → 重跑单物体轮次)。
