## 2. 今晚的**关键结论** (有完整证据链)

### 2.1 真根因: 判据的腕速那一条

到位 = 位置<1cm **且** 朝向<15° **且** 腕速<5cm/s **且** 保持 2 步。

| 判据 | 实测 | 结论 |
|---|---|---|
| 位置 | A 组摸到 **0.84cm** | ✅ 能进窗口 |
| 朝向 | 2.79° | ✅ 早就达标 |
| **腕速** | 固定步长恒定 **10cm/s** | ❌ **结构上不可能** |

`Minimal_L` 跑满 40M 步卡在 3.4cm、A 组摸到 0.84cm 却到位率 0 —— **同一个原因**。

**修法**: 恢复 `dyn_arm_near/far`(远松近紧), 近端 ≤2cm 时 1.5mm/步 = **3cm/s** < 5cm/s。
它一直在 cfg 里, 是 `--minimal` 把它关了(`minimal_fixed_res=True`)。现已改成**默认开启**,
要复现旧行为用 `--minimal_fixed_res`。

### 2.2 `V2_curr06` 是今晚唯一成功的 run (已存档)

* 配方: **有参考(退避路径) + 有课程**, 唯一变量 `--curr_start_target 0.6`(默认 0.3, 推进更保守)
* 评测在 **100% 和 0% 之间横跳**(ep500/700/800/1100 成, 600/900/1000 不成) —— 站在边界上没稳住
* **独立复现**: 拉回本地录像 **3/3 全成功**, 每回合约 94 步(预算 250)
* 存档: `logs/V2_curr06_pulled/eval_best.pth` + `videos/eval_best-step-0.mp4`

⟹ **判据可达是既成事实**, "1cm 在几何上不可能"那条猜想已排除。

### 2.3 用户对 `V2_curr06` 的三条不满 (下一步要解决)

1. **绕路**: 退避参考先跑到"目标外侧 24.6cm", 实测距离剖面 29.9 → 14.4 → 25.3 → 1.45cm
2. **抖动**: 档位幂次分布导致参考自己速度变化 **61 倍**(31.2 → 0.51 cm/s), 台阶式跳变
3. **要直接接近**, 不要插值回退

**已算好的替代方案**: 参考 = **站姿 → GraspPose 腕直线 + smoothstep**, 逐点 IK。
峰值 9.9cm/s、末端 0.22cm/s、单调下降、无跳变 —— 三条要求一次满足, 且"停得下来"免费。
**未验**: 这条直线会不会撞桌/撞物体(退避设计当初就是为规避此风险)。有现成的逐帧外壳间隙检查。

### 2.4 架构讨论 (用户裁定)

我曾建议"接近段交给规划器"。**用户否掉**, 理由成立: 双手协作(拧盖/拔 U 盘)是**多次接触—松开**,
规划器+RL 需要精确的任务分割模块, 而分割来自带噪声的重建, 脆且是新的失败源。

**澄清**: "参考轨迹" ≠ "规划器接管"。参考只是前馈提示, **策略全程控制**, 没有交接时刻,
也不需要任务分割。双手协作的参考天然来自人的示范重建, 覆盖全部阶段。

## 3. 双臂 (C/D) —— 今晚从零写通, 修了 13 个问题

`tasks/pregrasp/bimanual_env.py`(新) + `bimanual.py`(补) + `train.py --bimanual`。
架构: **env 单边逻辑不动, 外面换入换出侧状态, 同一份奖励/终止代码跑两遍**。

### ★ 最后那个架构级 bug (前面十几次都没修对的原因)

`SideState` 存的是**张量引用不是副本**。父类大量缓冲是**原地写**
(`self.obj_start_pos[env_ids] = ...`), 两侧引用同一块内存时原地写互相覆盖 ——
**字段明明在 SIDE_ATTRS 里、明明被"换"了, 换的却是指向同一块内存的两个引用**。

症状链: 两侧 `obj_start_pos` 都是杯子的 0.918m ⟹ A 把瓶子写到杯子位置 ⟹ 两物体重叠
⟹ PhysX 爆炸弹开到 1.25/1.52m ⟹ 判 `thrown` ⟹ 每步复位 ⟹ 冻结永远满 ⟹ **两只手一步没动过**。

**修**: 构造 B 侧后把张量**全部深拷贝**(137 项)。`bimanual.py` 原注释写着
"原地写两种方式都安全" —— **那句是错的**, 已更正。

### 其他要记的

* `SIDE_ATTRS` 从 82 项补到 **157 项**。补法不是靠关键词扫描(那个漏了 `ee_body`/`ee_id`,
  因为名字里没有任何关键词), 而是 `BM.list_uncovered()` **全量列举**后人工裁。
* **名字会骗人**: `table_bids` 不是"桌子的索引", 是"与桌/物做碰撞检查的**本侧手部连杆**"。
  同族还有 `self_bids`(用**对侧**前缀)、`shell_pts`(由 arm_bids 派生)。
  ⟹ **判断是否逐侧只能看它怎么算出来的, 不能看名字。**
* 检测器自己也有盲点: `list_uncovered` 第一版写了 `isinstance(v,dict) and v`, **空字典被跳过**,
  而 `_sig`/`_ep_sums` 构造时正好是空的 ⟹ 全绿而实际串台。已去掉 `and v`。
* 逐侧日志必须**平铺进 `extras` 顶层**(TB 只读顶层), 只改 `extras["log"]` 无效。
  现在是 `R/xxx`、`L/xxx` 两套 + 原 key 保留成两侧均值(下游按原名取)。
* **双臂改动横跨两个目录** (`tasks/pregrasp/` + `rl_rebuild/correction/env/`),
  只同步一半 = "本地能跑、远端崩"(实测 `force_side` 参数漏同步)。

## 6. 今晚的方法教训 (代价很大, 值得记)

1. **打印/核对"最终生效值", 不要相信"我写了这行代码"。** 今晚 ~6 次 bug 是同一形状:
   声明的意图与实际生效不一致(字段名对不上、被后面覆盖、改错了没人读的那份、横幅印的
   和实际不符)。唯一抓得到它们的手段都是同一个。
2. **问对问题比答对问题重要。** 双臂我一直问"还有哪个字段没登记", 补了几十个;
   真正该问的是"**登记了的字段, 两边是不是真的互不影响**"。问错时答对多少次都没用。
3. **别在实验还没跑完时下结论。** 我整晚主张"参考是负资产、课程锁死策略",
   依据是"四条带参考+课程的全 0%" —— 而 `V2_curr06` 是在 **16.4M 步**才第一次成功的,
   我在它成功之前就下了结论, 并用那个结论推动了后面一整轮方向。
4. **"最简化"可能简掉关键机制。** `--minimal` 为了"去掉所有花哨的", 把唯一的减速机制
   一起关了 ⟹ 40M 步测的不是"这个方法行不行", 而是"一个停不下来的策略行不行"。
