# 设计 → 训练 → 纠错 → 优化 闭环

这份文档是这个项目的**工作制度**, 不是设计说明. 设计说明在 `PHASE1_RESIDUAL_CORRECTION_DESIGN.md`
和 `MANUAL.md`; 这里只回答一件事:

> 我们设计的东西, 怎么在训练里**知道它对不对**; 数据说它不对时, 怎么**定位到是哪一条设计**,
> 以及**改哪一个参数**.

## 0. 为什么需要制度

这个任务的反馈极慢 (一条 run 数小时) 而且信号稀疏 (成功率长期是 0). 在这种条件下,
"训一版看看" 会退化成随机游走: 一次改三个参数, 曲线动了不知道是哪个起的作用,
曲线没动不知道是设计错了还是没训够. 制度的作用就是把这三件事分开:

| 分不清的东西 | 用什么分开 |
|---|---|
| 仪表在抖 vs 设计错了 | **§1 仪表层** —— 分母是回合窗口, 不是单步采样 |
| 哪一条设计错了 | **§2 台账** —— 每条设计事先写好证伪信号 |
| 该改哪个参数 | **§3 判读** —— 触发条件 → 唯一动作, 写死在 `diagnose.py` |

核心纪律只有一条: **假设和它的证伪条件必须写在训练之前.** 训完再解释曲线, 那是编故事.

## 1. 仪表层: 先让数字可信

### 1.1 原来的坑

env 只在 `_reset_idx` 里往 `self.extras` 写统计, 而 PPO 每步 `self.extra_info = {}`
重建, 只有 horizon **最后一步**那份进 TensorBoard (`ppo.py:439`). 于是曲线的分母是
"这一步恰好 reset 的那几个 env" —— 单点非 0 即 1. `CLAUDE.md` 第 2 条坑说的就是它.

**拿这种数推翻设计假设是危险的**: 你分不清曲线跳是设计错了还是仪表在抖.

### 1.2 现在

`env/diagnostics.py` 的 `EpisodeDiagnostics`: 逐 env 累计 → 回合结束推进环形缓冲 →
**每步**发布最近 `diag_window`(默认 256) 个完整回合的均值. 发布 0 维 tensor,
PPO 的 extras 过滤器直接吃, 且不触发 GPU 同步.

判读前先看 `diag/_window_n`: **小于 32 就别下任何结论** (规则 G1 会替你拦一次).

### 1.3 指标清单

每条指标存在的唯一理由是"它长成某个样子, 能说明某条设计错了". 加指标前先写出这句话,
写不出就别加.

| 指标 | 测什么 | 对应假设 |
|---|---|---|
| `diag/contact2_frac` | ≥2 指接触的时间占比 | A: 手指够得到 |
| `diag/contact_any_frac` | ≥1 指接触占比 | A |
| `diag/fres_used_deg` | 累积手指残差平均用量 (度) | B: rate/total 拆分 |
| `diag/fres_sat_frac` | 残差顶到 total 界的时间占比 | A/B |
| `diag/frate_util` | 手指动作幅度 ∈[0,1] | B: rate 是不是瓶颈 |
| `diag/obj_disturb_cm` | **抓住之前**物体被推开的峰值 | C: 权限会不会把物体碰跑 |
| `diag/lift_peak_cm` | 物体抬升峰值 | D: 握不握得住 |
| `diag/afford_hit` | 接触时指尖落在 affordance 区的强度 | E: affordance 顶不顶得上 GraspPose |
| `diag/rew_*` | 逐项奖励的每步均值 | F: 引导项有没有盖过任务核 |

## 2. 设计台账

每条 = 一个**可证伪**的断言. "证伪信号"列就是 `diagnose.py` 里的规则.

### 2.1 手指累积残差 (2026-07-27 上线)

**背景**: 原来 `finger_residual_max` 一个数同时当"每步扰动界"和"总权限界",
而这两个需求方向相反 —— 每步要小 (sigma×界=每步扰动, 大了扇飞物体, 实测 sigma=0.76
时接触率 0.1%、物体飞 37.7cm), 总量要大 (`calib_finger_geom` 实测指尖够到物体需
28~59°, 中位 45°; 5.7° 是**结构性**够不着). 一个数满足不了两个.

**改法**: 拆成 `finger_rate_max`(0.10 rad/步, 沿用标定过的安全值) +
`finger_total_max`(1.2 rad = 69° = 几何下界 ×1.5), 残差在步间累加, 钳在 total 界.
零动作仍然精确跟参考 (与臂的 `accumulate_action` 同构).

| # | 假设 | 证伪信号 | 若被推翻 |
|---|---|---|---|
| A1 | total 界够得到物体 | `contact2_frac<0.10` 且 `fres_sat_frac>0.40` | 先复核几何下界; 若下界已满足, 问题在腕/臂位姿而非手指界 |
| A2 | 策略会去用这份权限 | `contact2_frac<0.10` 且 `fres_sat_frac<0.05` 且 `frate_util<0.30` | 是信号/探索问题, **加 total 界无效** |
| B1 | rate 够温柔 | `obj_disturb_cm>2` 且 `contact2_frac<0.30` | 降 rate 或调大 `dyn_d_near`; **别动 total** |
| B2 | rate 不是瓶颈 | `frate_util>0.85` 且 `fres_sat_frac<0.20` | 提 rate ×1.5, 提完必须回看 B1 |

**已验证的实现事实** (2026-07-27, `Grasp2`, 常数 +1 动作):
残差在 24 步攒满 68.75° 后被钳住 (纯 rate 理论 12 步, 慢一倍是 `dyn_res` 在缩增量),
回合 reset 后归零. 即 rate/total/dyn_res 三者的分工按设计生效.

⚠ **那个几何下界是在 palm 锚下测的** (`calib_finger_geom.py`): 那时物体被按构造搬到
合拢中心正下方, "够不够得到"只差手指弯曲量. 换成 camera 锚 (§2.8) 之后手离物体
还差 16cm, 28~59° 这个区间不再成立 —— `finger_total_max=1.2` 的依据要在
**PreGrasp 由物体几何生成之后**重测.

**已知未定量**: total 界的**上界**测不出来 —— 它取决于探索噪声、物体质量/摩擦、
撞击动量, 是动力学+学习问题, 不是几何问题. 随机动作扫描给出的是噪声
(接触率在 0%/12%/38.7% 之间非单调跳), 因为 29 维随机噪声几乎不可能凑出协调抓握,
那个实验测的是"随机扰动的破坏力", 不是"策略能不能用好这个自由度". **只能靠 B1 在训练里定.**

### 2.2 无 GraspPose 设定下的奖励 (2026-07-27 上线)

**背景**: 甜甜圈这类物体 BODex 出不了 GraspPose, 没有 GraspPose 就没有 cuRobo,
于是参考手部轨迹里**没有任何一段是验证过可行的**: 参考手指 = 人手重建 + retarget 的产物,
是全链路噪声最大的量.

**推论**: 拿它当模仿目标 = 奖励"别修正", 与本项目的前提 (修正带噪重建) 直接矛盾,
也与刚给出的 69° 权限对着干.

**改法**:
- `imit_finger_w = 0` —— `r_imit` 只保留腕位锚定, 手指姿态自由
- `traj_after_contact = 0` —— 接触**后**不再逐帧跟随重建的物体轨迹
- 接触**前**的 `r_traj` 保留: 那一段的实际含义是"别把物体碰跑", 手指有 69° 权限时更需要
- 抓法改由 `contact` + `afford` + `lift` 三项定义 —— 全是物理/接触信号, 不依赖 GraspPose

| # | 假设 | 证伪信号 | 若被推翻 |
|---|---|---|---|
| C1 | 接触上就握得住 | `contact2_frac>0.30` 且 `lift_peak_cm<3` | 看 `afford_hit`: 低=接触点不对, 高=力不够 |
| C2 | affordance 顶替得了 GraspPose | `afford_hit<0.10` | 查热图坐标系对齐 → 提 `lam_afford` → 都不行则该 clip 的 B 组设定不成立 |
| E1 | 引导项不压过任务核 | `Σ|rew_引导| > 3×|rew_task|` 且 `sr<0.10` | 压 `lam_*`, 优先压 imit/traj |

⚠ `train.py` 里有个自适应 imitation 调度 (`f = 0.2 + 0.8·min(sr_ema/0.3, 1)`) 会随成功率
**上调** `lam_imit`/`lam_traj`. 它和上面两个开关是正交的 (开关控通道, 调度控总权重),
但读 E1 时要记得权重是动的.

### 2.4 accum run 的判读 (2026-07-27, 8M steps, 240 迭代)

**站得住的结论** (这几条量都有界, 不受下面那两个仪表 bug 影响):

| 指标 | 早段 → 末段 | 基线 full2 | 读法 |
|---|---|---|---|
| `contact2_frac` | 0.018 → **0.765** | — | 累积残差**成立**: 手指真的够到物体了 |
| `fres_sat_frac` | 0.21 → **0.825** | — | 69° 被吃满 —— total 是绑定约束 |
| `frate_util` | 0.08 → 0.094 | — | 每步幅度几乎没用满却攒满总量 = 积分器按设计工作 |
| `term/obj_div` | 0.188 → **0.039** | 0.130 | 打飞率比基线低 |
| `success_rate_ema` | 0.011 → **0.029** | **0.098** | **比基线差** |

§2.1 的假设 A1/A2/B1/B2 **都没被推翻**. 接触问题是真解决了.

**真正的问题 (规则 T1)**: 这个配置 (`grasp_only=False`) 的成功判据是
`_success_step`: **物体最终落在人手结束交互位 `place_tol`(8cm) 内**;
而 reward 的任务核 `r_task = lift × grip_gate × falling` 测的是**抬多高**.
两者不是同一件事. 策略把"抓住+抬起"学到了 (`rew_task` 1.37 / 满分 2.0),
成功率却没动 —— 它在最大化被测量的东西, 而那不是判据.

**这里有我自己造的一个洞**: `traj_after_contact=0` 关掉了接触后的逐帧跟随,
而在完整轨迹任务里 `r_traj` 是**唯一**指向放置目标的稠密信号. 关掉它 =
把唯一的方向感也一起删了. 判断"逐帧钉带噪路径没道理"是对的, 但**不该在没有
替代信号的情况下删**.

**下一步 (单个改动)**: 加**终点势函数** —— 奖励物体到目标位距离的减少
(势差分, 与 approach 同一形式). 它只钉判据本身, 不钉中间路径, 正好避开
"重建路径带噪"这个反对理由. 不是把 `traj_after_contact` 改回 1.0.

### 2.5 仪表 bug (在这次判读中被抓到, 已修)

两个 bug 让第一版判读**不可信**, 教训是仪表本身也要被证伪:

1. **发散回合污染 max 类统计**: `obj_disturb_cm` 读出 51593cm(515 米).
   物理发散的回合物体跑到几百米外, 而这是"回合内 max、窗口内 mean"的量,
   一个发散回合就顶爆 256 个回合的均值. 已修: 钳到 100cm + 超界单独计
   `diverge_frac`("发散了几成"本来就该是独立信息).
2. **逐项奖励记了未钳制的值**: `compute_reward` 返回的 `terms` 是原始值,
   策略实际拿到的是 `clamp(min=term_clamp=-10)` 之后的. `rew_approach` 记成 -40,
   而它的真实影响上限是 -10 —— **E1 那条"引导项压过任务核"就是被这个数字触发的,
   是假阳性**. 已修: 按 `term_clamp` 钳后再记.
3. **空掩码回合记 0 而不是 NaN** (顺带发现): `afford_hit` 的掩码是"有接触",
   整回合没碰到的 env 被记成 0.0 拉低均值 —— 读出来像"接触点很差", 实际是
   "根本没接触". `place_err_cm` 更危险: 没走到 hold 段的回合记 0cm =
   **看起来像完美放置**. 已修: 记 NaN + `nanmean`, 并发布 `__cov` 覆盖率.

⚠ 这三条修复对**已经跑完的 run 无效** (数据已经落盘). accum run 的
`obj_disturb_cm` / `lift_peak_cm` / `rew_*` / `afford_hit` 这几列不要引用.

### 2.6 自碰撞: 一个被当成 reward 问题的物理设置 (2026-07-28)

录像里看到手指交叉/穿模, 第一反应是"加自碰撞惩罚". 查下来是仿真器设置:

```
assets/vega_1p_sharpa_fixedtorso.usd
  /vega_1p_sharpa/root_joint :: physxArticulation:enabledSelfCollisions = False
```

**手指物理上就能互相穿过.** 给这种情况写 reward 惩罚, 是教策略遵守一个仿真器不执行的
约束 —— 学到的东西也不可能迁移到真机. 而 `dexmate_env_cfg.py` 开篇写的设计意图正相反:
"限位/自碰撞/奇异位形/力矩上限 全部由仿真器天然执行, 不再靠 reward 惩罚去劝".

**零动作冒烟对照** (Grasp2, 16 env):

| | 自碰撞关 | 自碰撞开 |
|---|---|---|
| 自锁 | — | 没有, 臂正常运动 |
| ≥2 指接触 | 0.6% | **16.6%** |
| 臂跟踪中位 | 15.51cm | 13.05cm |
| **力矩饱和中位** | **0.242** | **0.957** ⚠ |

接触率涨 27 倍 (手指不再互相穿插, 被迫张成正常包络), 但**电机力矩中位饱和度冲到 0.96**.
`arm_residual_max` 那段注释记着这个后果: 力矩顶满时"策略的残差静默失效, 信用分配被污染".

所以它**不是免费的修复**, 必须当独立变量验证 —— 这也是把它从原计划的 Run B 提前到
Run A 的原因: 在允许穿模的物理上测终点势, 结论到了下一条 run 就作废.

| # | 假设 | 证伪信号 | 若被推翻 |
|---|---|---|---|
| J1 | 策略的残差出得了力 | `torque_sat_frac > 0.50` | 查相邻连杆碰撞过滤, 不要继续调 reward |
| K1 | 回合不是被卡死终止的 | `term/stuck > 0.20` | 走不到 hold 段, 成功率结构上是 0 |

**结论: 自碰撞开启被数据推翻 (2026-07-28, 87/240 迭代提前终止)**

```
term/stuck        0.965      ← 96.5% 的回合以"臂持续追不上目标"终止
success_rate_ema  0.0013
torque_sat_frac   0.257      ← 力矩饱和反而不是主因
```

K1 决定性触发。**臂自锁**, 不是力矩不够。零动作冒烟之所以没抓到, 是因为零动作沿着
**可行参考**走; 策略的残差一施加就把自己卡进自碰撞。

⚠ 这条结论**只有在 `term/stuck` 上线之后才看得见** —— 它是 2026-07-28 才补的(之前
`_last_stuck` 算出来从不写日志)。没有它, 现象是"接触率 58%、成功率 0", 完全无从解释。
这是"仪表缺一条就诊断不出病"的实例。

**代价数据**: 自碰撞开启使吞吐从 2300 降到 **927 FPS**(2.5x)。即便它有边际收益, 这个
代价也要单独权衡。

**下一步不是继续调 reward**, 而是: ① 检查 USD 相邻连杆的碰撞过滤是否缺失(自锁的直接原因);
② 修好过滤再重测。在那之前, 自碰撞保持关闭。

### 2.7 终点势函数 (2026-07-28 上线)

替代被删掉的 `traj_after_contact`, 补上"物体该去哪"的方向信号:

```python
r_goal = (d_prev − d) / sigma_goal * gate      # d = ‖obj − ref_obj[L-1]‖
```

三个设计点, 每个都有对应的坑:

1. **势差分而非年金** —— 停在原地零收入, 远离付负. 与 `approach` 同形式.
2. **门控 (latch)** —— 连续 `goal_gate_steps`(10 步 = 0.5s) ≥2 指接触才开门, 之后保持整回合.
   防"推/撞/抛把物体轰向目标"刷分 (录像里已看到这种行为). 用 latch 是因为一次滑脱
   不该把方向信号整个剁断.
3. **权重量纲** —— 势函数整条 episode 只付 `(d起−d终)/σ` 一个总和. Grasp2 物体总位移
   仅 0.19m, σ=0.1 → 总量 1.9 单位; 沿用 shaping 环的 0.5 则整条 episode 只值 **0.95 分**,
   而 episode reward 是 467 (task 年金就占 364) —— **完全是噪声, 加了等于没加**.
   `lam_goal=20` 使总量 ≈38, 与 contact 年金 (0.14×266≈38) 同量级.

⚠ `prev_goal_dist` **每步都更新**, 与门开没开无关. 只在门开时更新的话, 门打开那一刻
prev 还是回合开始的旧值, 会一次性白送整段距离的横财 (离线单测已覆盖这条).

⚠ 门控状态**进观测**: 奖励依赖一个 latch, 策略就必须看得见, 否则信用分配是瞎的.
观测 194 → 195.

| # | 假设 | 证伪信号 | 若被推翻 |
|---|---|---|---|
| H1 | 门确实会打开 | `goal_gate_frac < 0.05` | 门太严, 放宽到 5 步或 ≥1 指; 门没开之前一切结论不成立 |
| H2 | 形成的是稳定抓取 | `grip_drift_cm > 5` | 加手物相对位姿稳定项; 终点势只管去哪, 不管怎么被带过去 |
| I1 | 不是靠"打"物体 | `fast_frac > 0.10` | `pen_spike` 被 term_clamp 钳死, 甩飞边际成本为零 —— 改惩罚形状 |

### 2.8 摆放换锚: palm -> camera (2026-07-28 上线)

**背景**: 旧链条有**两个锚, 都绑在物体上**, 后一个破坏前一个 ——
`align_replay` 把物体首帧 xy 放到原点 (手/物/相机相对关系 = 重建原样),
`replay_grasp` 又把物体搬到 PreGrasp 合拢中心正下方. 实测 Grasp0~9 **全部**:
物体落到机器人左侧 y=+0.141 而交互手是右手, 每条 clip 都是跨中线的**跨身抓取**.

**改法** (`anchor_mode="camera"`, `place_camera.py`):
xy 由"重建相机(人头) -> 机器人 ZED 光心"刚体同步平移, 三者相对关系不动;
z 是两条**独立**约束 (物体贴桌 / 手**全程**最小抬升到 clearance).
ref builder 用常数 `ZED_NOMINAL` 摆, env 在躯干收敛后用**实测** ZED 补残差
(`_recheck_camera_anchor`) —— 常数漂了会打印并补上, 不会静默摆错.

**实测 (Grasp2, `check_placement --clip Grasp2`)**:

| | palm 锚(旧) | camera 锚(新) |
|---|---|---|
| 物体 xy | (0.063, 0.141) 左 | (-0.051, -0.083) **右, 与交互手同侧** |
| 物体→交互手 | 37.0cm | **17.3cm** |
| 手最低点−桌面 | −1.66cm | **+6.61cm** |
| 手穿桌帧数 | 56/166 | **0/166** |
| 全程最小抬升 | (只保 PreGrasp 单帧) | **0.00cm** —— 撤掉旧锚后重建腕高本来就够 |
| IK 全程可达 | 100% | 100% (**没变**, 可达性不是这条改动的收益) |

⚠ 换锚改变物体位置与腕轨迹, **旧 checkpoint 的观测分布对不上**; 2026-07-27~28 那
五条 run 的结论只在 palm 锚下成立.

### 2.14 死亡机制判读: 起步竞速, 不是步长 (2026-08-03, 5 条 40M 全程时间线)

6 条 kl-0.02 系配方 2 活 4 死. 逐 M 步时间线 (timeline.py) 给出的机制:

**死法 = 输掉"起步竞速"**. 两个起步分支共享一张网, 前 ~3M 步是竞速窗口:
- **B(活)**: grasp 在课程一动没动时就自己冲到 0.52@3M → 0.91@7M —— **先巩固, 后开荒**,
  接近段的失败梯度冲不动已巩固的技能.
- **N1/N2/N3(死)**: grasp 前 3M 只有 0.00~0.10, 从未巩固; 50% 接近回合的持续失败
  梯度把这点萌芽冲掉 (N1 2.2M 死 / N2 1.2M / N3 1.4M). kl 0.05→0.02→0.01 只改冲刷
  速度, 不改结局 ⟹ **trust region 调不出稳定性, 病根是训练顺序不受控**.
- 死后课程照常运转是**盲区**: 可行性课程只看 arrive_rate, N1 在 grasp=0.000 的情况下
  把 eps 一路收满 1.04 / arrive 练到 1.00 —— 系统在优化一个残缺任务而毫无察觉.

**复活是真实存在的第二条路**: S1 在 1.1M 就死了, 但 **20.3M 复活** → 40M 时 grasp 1.00/
端到端 0.967. 复活条件 (与 N1 对照): 接近段先彻底掌握 (S1 的 arrive≈1 且 eps 收满发生在
15~17M, 死网复活还剩 20M+ 跑道; N1 到 31M 才掌握, 只剩 9M, 没复活). 机制推测: arrive
掌握后, 接近分支的回合大量抵达 GraspPose 进入抓取相位, 抓取训练数据从 50% 直接分支
扩到 ~100% 回合, 同时"接近失败"梯度消失 —— 压制源没了, 数据翻倍, 技能重新长出来.

**推论 (下一台账条目的候选设计, 未预注册)**: 把竞速变成**顺序** —— 先 `dgp=1.0` 纯抓取
训到 `sr/from_grasp ≥ 0.9` 再开接近 (或直接从 PreGrasp 冠军/B/S1 的 ckpt 热启动开荒).
B 的运气 = 种子恰好先学会抓取; 顺序化就是把这个运气写成制度.

## 4. 循环怎么跑

```
   ┌──────────────────────────────────────────────┐
   │ ① 设计: 写下假设 + 证伪信号 (§2 台账)         │
   │    没有证伪信号的改动 = 不允许上线            │
   ├──────────────────────────────────────────────┤
   │ ② 训练: 一次只改**一个**参数                  │
   │    run 名带上改了什么 (如 _frate015)          │
   ├──────────────────────────────────────────────┤
   │ ③ 判读: diagnose.py <run> --vs <上一版>       │
   │    先看 _window_n 够不够, 再看哪条被推翻       │
   ├──────────────────────────────────────────────┤
   │ ④ 优化: 按台账"若被推翻"列的动作改            │
   │    没有规则触发 -> 说明瓶颈不在已建模的维度,   │
   │    该补的是**新假设 + 新指标**, 不是乱调参     │
   └──────────────────────────────────────────────┘
```

几条硬规矩:

1. **一次一个参数.** 两个一起改, 判读表全部失效.
2. **成功率只认 `eval_policy.py`** (`CLAUDE.md` 第 2 条). TB 的 `success_rate` 用来看趋势,
   定论要跑确定性评测.
3. **规则没触发 ≠ 设计没问题**, 只等于"没触发已建模的那几条". 这时候的正确动作是补台账,
   不是继续调参.
4. **改完记台账.** §2 的表要跟着改动走 —— 台账过期, 整套制度就退回到"训一版看看".

### 关于 accum 这条 run 的一个坦白

它一次带了**三个**改动 (累积残差 / 关手指模仿 / 关接触后跟随), 违反 §4 的"一次一个参数".
理由是三者耦合: 给了 69° 权限之后, 手指模仿项会直接反向拉住这份权限, 单独跑"只累积"
测的是一个自相矛盾的配置. 代价是**归因会模糊** —— 若判读结果不干净 (比如 A2 与 E1 同时
触发), 下一步必须拆成 a) 只累积 (imit_finger_w 保持 0.5) 与 b) 累积+关跟随 两条对比,
不能继续叠改动.
