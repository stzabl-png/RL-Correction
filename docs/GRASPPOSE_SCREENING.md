# GraspPose 筛选规范

> 给定一批 Dexonomy 生成的 GraspPose 候选, 判断哪个能当训练的 prior 用。
> 立项依据见 `DESIGN_LOOP.md` 2026-07-31/08-01 各条; 用法见 `PREGRASP_MANUAL.md` §4.6。
> 最后更新: 2026-08-01

---

## 0. 为什么需要这一套

上游 Dexonomy 的 Isaac 验证（走 `ocir-grasp-synthesis` 的 server）**对本平台没有预测力**。
它不是做错了，是**测的不是同一件事**：

| | OCIR 验证器 | 训练 env |
|---|---|---|
| 手怎么装 | palm 零偏移 `PhysicsFixedJoint` **焊死世界**, 逐帧刚体传送 | DexMate 7-DOF 臂, 位控 + IK |
| 根动力学 | 无（连浮动根都没有）| 臂会被反作用力推动 |
| 摩擦 | 手和物体**全身** 3.0/3.0 multiply | 仅 5 个 elastomer 垫 9.0, 其余 **0.6** |
| 接触体 | `required_cbody` = 5 个 `*_DP` 壳 | 力传感器只读 elastomer 垫（凸出于 DP 之外）|
| 工作空间 | **无**（没有臂 ⟹ 物体 yaw 是自由的）| 有（yaw 决定够不够得着）|

固定基座下"拇指压 20N"毫无代价，全身摩擦 3.0 意味着 DP 壳自己就能提供摩擦。
所以它判"能抓起"对我们不构成证据。

**实证（pp1 全部 4 个候选）**: 验证器保留的 `44_6` 训练失败; 它毙掉的 `21_7`/`32_2`
在可达性上反而更好（贴着视频 yaw）。但要注意——**验证器在它自己那个轴上排序是对的**:
`44_6` 的 Q\* 确实是四个里最好的。它只是看不见可达性那一维。

⚠ **推论: 不要用 `isaac_succ/` 当候选池。** 保留 Dexonomy 的**生成**能力, 丢弃它的**筛选**结论,
`grasp_data_isaac_failed/` 里的候选必须一并纳入筛选。

## 1. 三关结构

```
Gate 0   数据同一性     秒级   离线         不过 = 数据问题, 不是候选问题
Gate 1   可达性         ~1min  离线(无GPU)  不过 = 物理上够不着, 再好的策略也没用
Gate 1b  人手一致性 H3  —— **已作废 (2026-08-02)**, 见下文; G 仅作排序键
Gate 2   prior 质量     ~3min  Isaac        不过 = 训不出来
```

**Gate 1 是唯一能强制"物体 yaw 与视频一致"的地方。** 现在的流水线在这一点上是反的:

```
现状:  抓姿定死  →  搜 yaw 使它可达      (yaw 成自由变量, 视频被牺牲)
应改:  yaw 定在视频 →  搜候选使它可达      (候选成自由变量, 视频被保住)
```

## 2. 判据

### Gate 0 — 数据同一性（不过就停）

- 重建 mesh 的 OBB 与 Dexonomy `info/simplified.json` 的 `obb` 逐位吻合（±0.5mm）
- prior npz 含 `canon_rot`（缺 = 老版本, 重跑 `make_prior.py`）
- 22 维手指关节序已从 `GENERIC_JOINT_ORDER` 换到 USD 序（`_generic_perm`）

### Gate 1 — 可达性（离线 IK, 5° 步长扫 360°）

对每个 yaw: 把抓姿随物体转到该 yaw, 解臂 IK。

| 量 | 定义 |
|---|---|
| `Ψ` | {yaw : IK pos_err < 1cm} —— 可达带 |
| `Δψ` | `Ψ` 到**视频 yaw** 的最小角距 |
| `\|Ψ\|/72` | yaw 鲁棒性（对摆放误差的容忍度）|

**硬判据**: `Ψ ≠ ∅`
**视频一致性判据**: `Δψ ≤ 10°`（**严格档, 2026-08-01 用户定**）

> 定这么严的代价是通过率低。对策不是放宽 `tol`, 而是**多生成几轮候选**（见 §6）——
> 物体摆放要忠于视频是任务的前提, 不是可以拿来交易的旋钮。

通过的候选, **训练时必须把 Gate 1 给出的 `best_yaw` 钉进摆放**, 否则 prior 加载器
会自己搜 IK 最优 yaw, 又把视频一致性丢掉（这正是 Grasp1 偏 136.5° 的成因）。

实测（pp1 四候选, 视频 yaw = 73.5°）:

| 候选 | Ψ | \|Ψ\|/72 | Δψ |
|---|---|---|---|
| 44_6 | 195°–325° | 27 | **108°** |
| 21_7 | 75°–210° | 28 | **2°** |
| 32_2 | 20°–290° | 55 | **2°** |
| 15_4 | 0°–20°, 140°–275° | 33 | 54° |

### ~~Gate 1b — 人手一致性 `H3`~~ **已作废（2026-08-02）**

> ⚠ **不要再用这一关。** H3 是为"把人手轨迹平移到 GraspPose、用管壁容纳缺口"那套设计
> 服务的。2026-08-02 定了方案 C（`pregrasp_align` 关掉、人手轨迹一点不平移），
> 管壁与 `R_hi` 一并删除，H3 失去依附。
>
> 另外两条使它本就站不住的证据：① 判死线 `R_hi ≤ 20cm`（⟹ `G ≤ 11.5cm`）是**拍的**，
> 而 Grasp3 的 56 个候选 `G` 从 3.3 到 14.7cm **连续无断层**，这条线是硬插进去的；
> ② `G` 掺了流水线参数 `hover_gap=8cm`，不是纯数据属性。
> `G` 保留为**诊断量/排序键**（缺口小的优先训），不再判死。
>
> 以下内容仅作历史记录。

### （历史）Gate 1b — 人手一致性 `H3`（2026-08-01 加入，08-02 作废）

> 只在**接近段任务**（`pick_lift`, 见 `PLAN_PICK_LIFT.md`）下是硬判据；
> 纯抓取任务（手已在 prior 位姿上起步）不受此约束。

接近段的参考是重建的人手腕轨迹，**不允许平移/warp**（统一摆放 + 绝对位置不可信）。
所以人手轨迹终点与该 GraspPose 之间的缺口，只能由**管壁放大**来容纳：

```
G      = ‖wrist_ref[gs] − wrist_grasp‖                 人手 PreGrasp 帧腕位 → 抓姿腕位
R_hi   = G / tube_soft_frac + jitter + slack           管壁末端要开到多大
       = G / 0.7 + 0.015 + 0.02
```

**H3**: `R_hi ≤ tube_r_cap`（建议 **0.20 m**）

超了 = 该抓姿要求手最终跑到离人手轨迹很远、朝向差很多的地方，等于"完全不按人的抓法抓"。
此时管壁形同虚设，人手先验被架空 —— **在候选阶段判死，不要靠开大管壁去迁就它**。

实测（视频 yaw 下, 2026-08-01）:

| clip / 候选 | `G` | 姿态差 | `R_hi` | H3 | 训练结果 |
|---|---|---|---|---|---|
| Grasp3 | 6.8 cm | 85° | 13.1 cm | ✅ | ✅ 100% |
| Grasp1 / 44_6 | **16.5 cm** | **159°** | **27.1 cm** | ❌ | ❌ 回避塌缩 |
| Grasp5 / 43_8 | (10.8 cm) | (90°) | (19.0 cm) | ⚠ | ✅ 100% |

⚠ **Grasp5 那行不可用**：它的视频 yaw 拟合翻面残差 **131.8°** ≫ 15° 判死线，
大概率是环形对称把残差撑大（§本文 Gate 0 已注明"对称物体会掩盖错误"）。
对称物体的 yaw 判据本身病态，需按对称群取商后再算 —— **未解**。

H3 的可信度高于 affordance 排序：它用的是重建里**最可信的量**（腕位姿）在**最可信的
时刻**（交互起点），而 affordance 热图在 20 个物体里有 3 个没有任何点 heat>0.5，
且对 6 个已知成败候选的排序**方向是反的**（详见 `PLAN_PICK_LIFT.md §7.2`）。

### Gate 2 — prior 质量（Isaac, **训练 env 的物理**）

⚠ **用训练 env 的物理, 但不用训练的成功判据。** 物理必须一致（elastomer 摩擦、臂装载、
力传感器口径）——验证器错就错在这里。但判据不能一致, 理由见 §3。

测法: 扫**合拢深度** `c ∈ [0, closure_max]` × **每指残差** `δ ∈ ±delta_max`,
在这个动作子空间里取最优。记:

**硬判据（两条都是必要条件, 有机理, 不是拟合阈值）**

| # | 判据 | 机理 |
|---|---|---|
| **H1** | `pads* ≥ cfg.success_min_pads`（现 4）| 候选判据硬性要求 ≥4 垫**同时**有效接触。手调最优都拿不到 ⟹ 策略永远形不成候选 ⟹ 永远进不了验证段。与奖励设计、训练时长**无关** |
| **H2** | `Q* > 0`，`Q = cent − 0.5·imb − 0.5·τ_n` | `cent_income = 0.1·max(0, Q)`。`Q ≤ 0` ⟹ "待在接触状态"的持续收入**恒等于零**, 而尝试接触要付超力/扰动代价 ⟹ 回避塌缩（台账里复发 4 次的失败模式）|

**诊断量（不设阈值, 用于归因失败模式）**

| 量 | 读法 |
|---|---|
| `imb` | 合力不对称度。→1.0 = 五力**零抵消**, 物理上夹不住任何东西 |
| `τ_n` | 归一净力矩。→2.0（钳位）= 一抬必转 |
| 单垫最大力占比 | >80% = 某一指独吞载荷（几何错配）|
| **悬崖检测** | 每指残差扫描中 `pads ≥ 4` 的档数。**0 档 = 悬崖**: 力在相邻两档间从十几 N 跳到 0N, 中间无过渡 ⟹ PPO 没有梯度可爬, **调奖励必然无效** |
| 标称位姿穿透量 | `c=1.0` 处单垫峰值力。远超 `squeeze_f_max` = elastomer/DP 系统偏移（见 §6）|

| Grasp5 (43_8) | **+0.070** | **4.94** | ✅ 100.00% @5.8M |

## 3. 明确**不采用**的判据（都附证伪证据）

| 候选判据 | 为什么不用 |
|---|---|
| **零动作能否抓起 / 并拢即抬** | **会毙掉 Grasp3**: 它零动作 `pads=2.66`、静态 `Q=−0.434`（比失败的 Grasp1 还差）、16 env×110 步**零候选**, 却训到了 100%。方向都是错的, 不是阈值松紧问题 |
| **静态贴合度 `d̄`**（五垫到物体表面距离均值）| **跨物体反向**。pp1 内部 4/4 单调（17.2/20.7/23.9/26.0 ↔ Q\* 递减）, 但两个成功 clip 是 Grasp3 **21.8mm** / Grasp5 **21.1mm**, 比失败的 44_6（17.2mm）**更远**。它量的是物体自身属性不是抓取质量 |
| **静态垫间距极差** | `15_4` 极差 2.4mm（四候选里最均匀, 看起来最像对称抓握）, 实际 `Q*` 最差（−0.522）、`τ_n` 1.41 逼近钳位 |
| **Dexonomy/OCIR Isaac 验证结果** | 见 §0 |
| **静态视图目视判断** | `21_7` 静态看拇指领先四指 7–9mm（比 44_6 的 3–4mm 更极端）, 动态实测力分配却是**反的**。静态只能看接近方向与包络, **不能判断力** |

> 共同教训: **判 prior 不是判抓取。** prior 的职责不是"它本身能抓",
> 而是"从它出发能学会抓" —— 要判它周围的**邻域**（可达最优 + 有没有梯度）, 不是判它这一个点。

## 4. 怎么跑 —— `tasks/pregrasp/screen_prior.py`

三关一次跑完, Gate 0/1 离线秒级, 只有幸存者才付 Isaac 的钱。

```bash
PY=/home/lyh/luhr/MagicSim/.venv/bin/python

# 一批 Dexonomy 候选 -> 三关全筛 (递归收 *_grasp.npy, 含 isaac_failed)
SHARPA_WANDB=0 PYTHONPATH=. $PY -u -m tasks.pregrasp.screen_prior \
    --clip Grasp1 \
    --grasp_dir /home/lyh/Project/Dexonomy/output/pp1_sharpa_wave \
    --info_json /home/lyh/Project/Dexonomy/assets/object/custom/processed_data/pp1/info/simplified.json

# 只跑离线两关 (几秒, 先看有没有必要开 Isaac)
    ... --offline_only

# 吃已转换好的 prior npz
    --prior_dir tasks/pregrasp/priors/<clip>_candidates
```

输出: 逐候选的判定表 + `<out_dir>/screen_report.json`（全部原始量, 便于事后复盘）。

内部测法（要复现或改判据时看这里）:
- **Gate 1**: 离线 IK, 5°×72 档, warm-start 沿扫描顺序传递; 物体摆放**离线算**
  （相机锚定 xy + canon 贴桌 z, 与 env 实测吻合 <0.05mm）; 视频 yaw 由
  `argmin_θ geodesic(Rz(θ)·R_canon, R_video)` 求出, 同时报**翻面残差**
  （>15° ⟹ canon 与视频朝下的面不一致, yaw 无意义）
- **Gate 2**: Isaac, 每候选一个**独立进程**（一个 session 建多个 env 不安全）;
  扫 6 档拇指残差 × 压到 `closure_max`, 每档稳态采 8 步, 取全域最优作 `Q*`/`pads*`

### 批次规则（2026-08-01 用户定）

```
生成一批  ->  整批过筛  ->  有通过的: 留下通过者, 丢弃其余
                       ->  全不通过: **整批都不保留**, 换参数再生成一批
```

不保留"矮子里拔将军"。Grasp1 的教训就是拿一个 `Q*=−0.141` 的候选硬训, 烧掉 12.9M 步。

⚠ Gate 2 的读数**近似 yaw 无关**（绕竖轴刚体旋转不改变手物接触几何, 也不改变重力相对物体的方向），
只有臂位形不同。所以在加载器选的 IK 最优 yaw 上测得的 `Q*`/`pads*` 对视频 yaw 附近同样成立。
但**臂位形会影响接触下的有效刚度**, 若最终要钉在某个 yaw 上训练, 值得在该 yaw 复测一次。

⚠ 三个扫描目前只在会话临时脚本里（`diag_depth` / `diag_balance` / `diag_oppose` / `diag_static`），
**尚未进仓**。要长期用需固化成 `tasks/pregrasp/screen_prior.py`。

## 5. 验证状态与未决

**已验证**
- `H1`/`H2` 在 6 次测量上与 3 次训练结果一致（2 正 1 负）
- `H1`/`H2` 与 OCIR 验证器在**它能看见的那一维**上排序一致（同判 `44_6` 为 pp1 最优）

**未验证 / 局限**
1. **训练结果样本只有 3 个**（Grasp3 ✅ / Grasp5 ✅ / Grasp1 ❌）。判据是**必要条件**,
   过了不保证训得出来。
2. **全部是回顾性的**。前瞻验证 = 下一个新物体先预测再训练, 记录预测与结果。
3. `H2` 的通过侧余量很薄（+0.070 / +0.074, 离 0 只有 0.07）。若出现 `Q* ∈ (0, 0.05)`
   的候选, 当前数据判不了。
4. 诊断量的阈值（`imb`/`τ_n`/独吞占比）**没有标定**, 只用于归因不用于判定。
5. **`tol=10°` 是"严格档"的取值, 本身没有实证依据** —— 它是任务约束（摆放忠于视频）,
   不是从数据学出来的。若将来允许"长轴对称"（长条转 180° 长轴方向不变）, 可达带会放宽近一倍,
   但那是**放宽任务定义**, 要单独决策并记账。

## 6. 重新生成一批抓取数据时

按影响从大到小:

1. **候选数量是硬瓶颈。** pp1 合成阶段只产出 **4 个**（pp3 有 126、pp5 有 68）。
   4 个里挑不出同时过 Gate 1+2 的。**每个物体至少要有几十个候选**才谈得上筛选。
2. **修 elastomer/DP 偏移。** Dexonomy 的 `hand_cbody`/`required_cbody` 是 5 个 `*_DP` 指节壳,
   而我们的 elastomer 垫**凸出于 DP 之外** ⟹ 标称"接触"位姿在物理上已穿透。
   实测标称位姿单垫峰值力: 12.7 / 14.5 / 22.3 / 38.4 N（门槛 8N）。
   这是**所有候选共同的税**, 修了它整批候选的通过率会一起上移。
   改法: 用"接触体 = elastomer 垫面"的模板重新生成。
3. **保留全部候选, 不要用 `isaac_succ/` 过滤**（见 §0 推论）。
4. **生成时就把可达性纳入目标**（若上游支持）: 物体钉在视频 yaw, 只接受腕位姿落在
   DexMate 工作空间内的抓姿。这等于把 Gate 1 前移到生成阶段, 比事后筛效率高得多。

### 生成命令（Dexonomy 侧）

必须在 `/home/lyh/Project/Dexonomy` 目录、`dexonomy` conda 环境下跑, 且**单行**
（该仓 `CLAUDE.md` 的约定: 多行反斜杠粘贴易断）。

```bash
TMPL=<模板> EPOCH=<轮数> tools/grasp_pipeline.sh <mesh.obj> <oid>
```

| 旋钮 | 默认 | 说明 |
|---|---|---|
| `TMPL` | `fingertip_mid` | 抓型模板, 见下表 |
| `EPOCH` | 50 | init 采样轮数, **约 10 候选/轮** —— 候选不够就加这个 |
| `KEEP_SERVER` | 0 | 连着跑多批设 1, 省 Isaac server 启停 |

可用模板（`assets/hand/sharpa_wave/init_tmpl/`）:
`fingertip_mid` · `fingertip_small` · `1_Large_Diameter` · `3_Medium_Wrap` ·
`isaac_8_7` · `isaac_15_1` · `isaac_26_8` · `isaac_45_7`

**已处理物体的产出对照**（`Dexonomy/tools/GRASP_PIPELINE_MANUAL.md`）:

| 物体 | OBB (cm) | 自然抓取成功数 |
|---|---|---|
| pp0 瓶(立) | 4.7 × 7.6 × 18.1 | 35 |
| **pp1** | **3.7 × 8.1 × 11.7** | **1** ← 异常少 |
| pp2 环 | 2.6 × 7.7 × 7.7 | 4 |
| pp3 | 2.6 × 3.9 × 3.9 | 16 |
| pp5 环(螺母) | 2.5 × 5.8 × 5.8 | 9 |

pp1 的稀缺不是尺寸问题（pp0 更大却有 35 个）, 更像**呈现姿态**问题: 它平躺时是
8.1×11.7cm 的宽扁板、厚仅 3.7cm, 指尖精抓模板（`fingertip_mid`）在这种面上很难落点。
换缠绕类模板（`3_Medium_Wrap` / `1_Large_Diameter`）是下一批该试的方向。

⚠ 每批用**不同的 `oid`**（如 `pp1_b2`）, 别覆盖上一批 —— 否则失败批次的证据没了,
也踩不到 Dexonomy 的 `skip_done` 坑（重跑同一 exp 的某个 op 前要删 `output/<exp>/log/<op>_*/`）。
