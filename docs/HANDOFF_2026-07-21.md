## 🔑 今天的核心结论 (推翻了早上那版的全部归因)

早上以为的原因 —— 物理参数不对齐 / 摩擦绑定 / GraspPose 质量 / 物体摆放 / approach 鸿沟
—— **全部排除**。用 `phys_ablation.py` 逐一量过:

1. **零残差回放本身就能抓** (53% 时间 ≥2 指接触, 抬 6.8cm, return +199)。环境和参考一直是好的。
2. **但加上探索噪声就全毁**: sigma=0.05 接触率掉到 3.6%; 训练实测 sigma=0.76 时接触 0.1%、
   物体被打飞 37.7cm (= `term/obj_div`=1.000)。**动作尺度才是根因。**
3. **物理参数"对齐 OCIR 验证器"是错的方向** —— 三项对齐(depenetration/求解器迭代/rest_offset)
   全都让结果变差(6.81→0.52cm)。那些参数与 OCIR 的逐关节驱动整定、不同 USD 资产是耦合的。
4. **OCIR 验证器的 `ok:true` 是运动学可行性证明,不是动力学可执行性证明** —— 它的手是
   `PhysicsFixedJoint` 锚定的运动学搬运(接触零退让、无限有效力), RL 侧是浮动根 wrench-PD。
   拿它当"RL 的成功案例"是范畴错误。

## 🔧 让它跑通的四处改动 (都做成了配置项, 缺省=旧行为)

| 参数 | 旧 → 新 | 位置 | 为什么 |
|---|---|---|---|
| 残差界 | 0.15m/0.3/0.3 → **0.02m/0.05/0.10** | `correction_env_cfg.py` | sigma×界 = 每步扰动量, 容忍度是毫米级 |
| `sigma_init` | 无(exp(0)=1.0) → **0.1** | yaml + `models.py` | 旧初值让策略一开始就 ±11cm 抖腕 |
| `mu_init_scale` | 无 → **0.01** | yaml + `models.py` | mu 头本是随机初始化, 初始策略是 obs 的随机投影而非零残差 |
| `critic_warmup_iters` | 无 → **50** | yaml + `ppo.py` | critic 随机初始化时 advantage 是噪声, 会把 mu 推走 |
| `max_lr` / `min_lr` | 1e-2/1e-6 → **3e-4/3e-5** | yaml + `ppo.py` | 见下 |

⚠️ **`AdaptiveScheduler` 是今天栽得最惨的地方 —— 两侧都会失控:**
- `kl_threshold=0.02` 时: lr 塌到 1e-5, 策略冻死在坏位置
- 改成 0.05 后: KL 长期低于加速线, lr 每轮 ×1.5 冲到 5.1e-3, 把已学到 task=0.41 的策略打烂
- 修法: `max_lr` = 初始 lr ⟹ **只能减速不能加速**(非对称信赖域)。残差修正需要慢而稳。
- 另注: warmup 期 actor 不动 → KL≈0 → 调度器会把 lr 顶到 max_lr, 所以 warmup 期同时跳过 lr 调度。

## 📐 当前任务定义 (grasp_only 模式, 单物体 MVP)

```
静置 20 步  | 手停 PreGrasp(cuRobo close 起点=帧50), 物体钉桌上沉降
RL 抓取 60  | ★学这段★ 参考=cuRobo close+squeeze(帧50→109), 策略出 28 维残差
硬编码抬升 20| 腕目标 z 匀速 +10cm (_lift_prog), 策略仍可微调保持握持
hold 40     | 腕不动, 判成功
= 140 步
```
`grasp_only=True` 时三处配套修正(不改会静默失效):
- `_ref_t` 钳在 grasp_end 后, 原 `in_hold = _ref_t()>=L-1` **永远不成立** → hold_ok 恒 0 → 成功率永远 0
- `r_imit` 的腕参考要加上抬升量, 否则"提上去"本身被模仿项扣分
- `lam_traj=0`(抬升期物体本就该离开桌面参考位)
- `success_lift_height=0.08` < `lift_height=0.10`(手指柔顺必然微滑, 要求零滑移不合理)
