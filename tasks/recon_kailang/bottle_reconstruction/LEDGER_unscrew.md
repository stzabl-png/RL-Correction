# 扭开瓶盖任务 v1 — 设计台账 (2026-08-25)

按 `docs/DESIGN_LOOP.md` 的纪律: 假设和证伪条件写在训练之前; 判读窗口是
`diag/_window_n ≥ 32` 个完整回合, 不够就不下结论. 一次只改一个参数.

## 0. 任务定义

- clip: `screw_unscrew_cap1_task` (= assembled 螺旋场景 + robot_hand=right)
- 场景: 瓶身直立在桌上 (upright 投影), 帽预合拢在瓶口; 右手从帽正上方的
  IK 预抓姿起步 (对照 pregrasp v2 "起点=PreGrasp" 设计, 跳过接近段)
- 成功: `screw_angle` 拧满 2 圈 (720°) 触发 detach 释放 → 终止 +20
- 动作: 基类 29 维残差原样 (臂7 累积+tube, 指22 rate 5.7°/步 total 69°)
- 观测: 基类 386 + 任务 10 = 396

## 1. 用户裁定 (2026-08-25)

- **replay 时钟 = 15Hz** (信任 `replay_world.npz` 的 fps 元数据, 不采纳源视频 30fps).
  本任务 object_only 不回放人手轨迹, 当前只影响参考重采样; 将来接人手拧盖参考时
  速度/时长按 15Hz 算. `meta.json` 的 `retarget_clock_status` 由此关闭.
- 质量/摩擦沿用已验证水瓶场景: 瓶 0.53kg/0.5, 帽 0.003kg/0.4 (CAD 字节相同).

## 3. 已知风险 (声明, 不阻塞 v1)

1. **2 整圈需要重复换把**: j7 行程 <720°, 策略必须学会"拧-松-回-再拧"循环.
   这是任务的真实难度, v1 不做课程; `screw_deg` 的分布 (卡在 ~90°?) 会给出
   下一步课程设计的依据 (如: 达到部分角度给中间成功).
2. **22 维指残差无合拢模板**: DESIGN_LOOP §2.1 已知随机噪声难凑协调抓握.
   v1 赌"接触奖励 + 势差分"足以引导; U2 触发时的预案是合拢斜坡 (pregrasp v2 同款).
3. **无域随机化**: 场景确定. 本轮只回答"能不能学会拧", 不回答鲁棒性.
4. **帽转角真值**: 只认仿真 `screw_angle` (指尖驱动的物理转动积分), 不用重建的
   视觉转角 (README: 螺轴对称, 视觉不可观).

### v3: 数据姿势 + 物理平滑 + 螺旋真实化 (2026-08-25, 用户验收反馈驱动)

1. 腕参考 = 数据姿势: 右腕位置 = 盖轨迹 + 世界系恒定偏移 (锚在证据帧44; 接触前保持

## pk22 取证 (2026-08-27): 右手"永远一根指"= 拇指戳 + 局部最优锁死

**pk22 实测 (Dyn17 @8M 权重, 64 env 全回合)**:

- 拇指触盖瞬间, 各指到盖心: 拇 3.09cm | 食 8.21 | 中 10.17 | 环 8.20 | 小 15.12
- 次近指间隙差 **5.12cm** —— 初判"参考侧(腕姿态没对准)"

**交叉验证推翻初判 (Dyn12 vs Dyn15/17, 末5均)**:
| run | wrist_err | tip_cap | contact2 | screw |
|-----|-----------|---------|----------|-------|
| Dyn12 | 3.63cm | 4.30cm | **70%** | 693° |
| Dyn15 | 3.55cm | 4.43cm | 0 | 58° |
| Dyn17 | 3.61cm | 4.22cm | 0 | 241° |
腕位误差与指尖-盖距离**三者几乎相同**, 而 contact2 从 70% 塌到 0
→ 参考/几何可达性**没变**, 变的是策略选择的**手掌朝向** (wrist_err 只测
位置不测朝向). ∴ 不是参考侧问题, 是**局部最优**。

**⚠ 同时证伪我自己的 U29 结论**: 当时判"衰减在 4cm 边界诱发回避 → contact2=0",
U31 已把衰减整体回滚, 而 contact2 **仍为 0** —— 回滚没有恢复它。

因为 U30b 把阈值降到 270° 后**单指戳足以拧完并释放** (screw 241°,
release 31%, placed 5.9%) —— 制度上单指够用, 就没有理由回到三指。

**为什么加档治不好**: 从拇指戳走到三指捏, 中途必须先**失去**拇指接触
才能转腕 —— 收入先降后升的**山谷**。U32b 的 1/3 档 (0.0167/步) 远不足以
支付穿越山谷的代价。这解释了 U32b 为何身份纠正成功 (环小不碰盖是同向
微调) 而根数纠正失败 (需要跨越山谷)。

**U34 (候选, 待实施): 螺纹驱动按接触指数分级** —— 现 drive_mask 只要
"有接触"即全速拧. 改为拧转速率 ∝ 触盖 triad 指数 (1 指 1/3 速, 3 指全速).
优点: **无悬崖** —— 拇指戳仍能拧, 只是慢 3 倍, 拧转势 r_screw 每加一根指
就连续变多, 山谷被填平; 且与"人拧瓶盖要三指"的物理直觉一致.
风险: 直接砍到 1/3 速可能让当前 placed 5.9% 掉回 0 (拧不完 270° 就超时).
缓解: 速率下限设 1/2 而非 1/3, 或按 max(1, n_triad)/3 起步观察.
判据: 实施后 +6M cap_n_triad >1.5 且 placed 不低于实施前的一半。

## U34 (Dyn18 起): 慢拧 + 三指分级驱动 —— 用户裁定落地

**用户裁定 (2026-08-27)**: "不要太快的拧, 需要找准位置, 三根手指慢慢拧".

**归因 (pk22 + 本条)**: 拇指戳局部最优的**制度性根源**是螺纹建模 ——
`drive_mask = 任意1指接触` 且 `max_angular_velocity=20 rad/s (1146°/s)`,
270° 只需 5-6 个控制步. 单指戳一下就能拧完全程, 三指精捏毫无制度必要性.
∴ 这不是奖励不够, 是**任务定义允许了不该允许的解**.

**改动 (两处, 同一裁定的两个面)**:
① `clips.py` cap1 `max_angular_velocity_rad_s` **20.0 → 2.0**:
   拧满 270° 需持续驱动 ~2.6s (2.0 rad/s × 0.9 阻尼 × 0.045s/控制步
   ≈ 5.2°/步 × 52 步), 接近人手速度. ("不要太快")
② `screw_triad_drive=True` (DynCfg): 速率 ∝ 拇/食/中接触根数
   (1 指 1/3, 2 指 2/3, 3 指全速; 环/小不计). ("三根手指" + "找准位置")
   实现: env.py 的 drive_mask 本就是**乘性**因子, 传浮点增益即可 (已补文档).
   **无悬崖设计**: 单指仍拧得动只是慢 —— 每加一根指 r_screw 连续变多,
   填平了"先松拇指才能转腕"的收入山谷 (pk22 判定 U32b 加档失败的原因).
哨兵: 新 diag `screw_gain` (1/3=单指慢拧, 1.0=三指全速).

**已知代价 (预登记, 不算证伪)**: 当前策略靠单指全速拧才有 placed 5.9%;
改后单指有效速率降至原 1/30, 预期 placed 先掉到 ~0, 需重学三指手型才回升.
用户已明确"现在不需要完整的好动作", 接受该回撤.

**证伪判据 (Dyn18, 自 Dyn17 last.pth 热启)**:
- +6M `cap_n_triad` >1.5 且 `screw_gain` >0.5 → 分级驱动生效, 手型在改;
  若 n_triad 仍 ≈1.0 而 screw_deg 掉到 <50° → 三指几何**确实**不可达,
  升级为姿态侧 (右腕 roll 参考 / 预抓姿 R 重构), 而非继续调激励.
- +12M `placed` 应回到 ≥3% (证明慢拧+三指的解存在且可学).
- 反例守卫: 若 `cap_extra_frac` 显著上升 (环小裹盖凑数) → 说明策略在
  规避 triad 判定, 加环小触盖小额罚.

**机理 (代码 + ω_瓶 列佐证)**: U40b 修的是**扭矩估计**路径

omega_phys = (relative_ang * axis_w).sum(dim=1)   # = 盖ω − 瓶ω  ← 未修

且接触真值门**只管 tau_in, 管不到 omega_phys**。写回时
cap_ω = 瓶ω(k) + ω_screw, 下一步读到的
omega_phys(k+1) ≈ ω_screw + [瓶ω(k) − 瓶ω(k+1)]
—— **瓶身角速度波动被逐步累加进螺纹转速**。ω_瓶 列实测在 ±0.5 rad/s

误读") 在积分路径上的存活版本。

**这解释了全部现象**: 接触开门→瓶抖被积成 172°/秒的猛冲→顶到 4 rad/s
安全夹→手不再晃瓶→无燃料→drag 赢→~220° 回锁→弱握破不了 40 mN·m
静锁→冻死 300 步。录像里"来回搓"的退角也是同源 (抖动有正有负)。

**影响面**: U40 以来所有拧转成绩需重估, 含 run5 release 57% /
Dyn23 placed 93.4%。screw_deg / release / placed 全部不可信。

**修法 (待裁定)**: omega_phys 改成与 tau_in 同一口径 ——
盖侧矢量差分 (盖ω − 上一子步写入矢量) 投影当前轴, 并同上接触真值门;
即"只有真实作用在盖上的接触冲量能改变螺纹转速"。改完必须重跑
双门验收: 探针五段 + dyn 1M 幻影门, 并**新增一门**: 接触期滑移<0
或 τ驱动 与 ω 同号 (证明是手指在带)。

### U44b 更正: "转动非指尖驱动" 判断有误 —— 是**戳转**, 不是幻影

修复后负对照 (run7 26M ckpt + 已修物理) 行为几乎没变: 仍冲到 4 rad/s
安全夹。重做力学对账后发现 U44 的**归因**错了 (代码 bug 是真的, 但不是
猛冲的主因)。

**两处测量缺陷**:
1. `force_matrix_w` 是 **normal contact forces**（IsaacLab 源码原话），
   **不含摩擦力**; 且是"盖作用在指尖上"的力, 作用在盖上要反号。
2. 判 Δω 时漏了螺纹阻力。4 rad/s 下 drag = τk + b·ω = 135 mN·m,
   量级和接触力矩相当, 会主导符号。

**重算 (计入阻力, 反号取盖上力矩)**:
Δω_pred = (τ_接触 − τ_阻力)·dt_ctrl / I_eff, 与实测 Δω **符号一致 30/37
= 81%**, 多步量化吻合 (步113 +2.002 vs +1.952; 步107 −0.328 vs −0.308;
步124 −0.558 vs −0.458)。⇒ **盖的转动确实由指尖接触力矩驱动。**

**滑移>0 为何不构成幻影证据**: 它只排除了**摩擦驱动**, 排除不了**偏心
法向推**。手指顶在盖侧/盖沿上, 法向力作用线不过螺轴 => 产生真实力矩,
就像拨转旋钮。这时盖面完全可以跑在指尖前面。

**U44 代码 bug 仍然是真的, 修复保留**: ω 积分路径确实用着未经真值门的
`relative_ang`。但它的量级是**每子步**的瓶身 Δω (±0.5 rad/s 是每控制步
= 12 子步的幅度, 摊到子步约 ±0.04 rad/s), 与接触注入的 dw 同量级而非
压倒性。所以修是对的, 但我此前"U40 以来成绩全部作废"的断言**过头了** ——
修复前后行为几乎一致, run5/Dyn23 的成绩不因 U44 失效。

**真正的问题 (回到用户最初的质询, 它成立)**: 策略是**戳转**而非**握拧**
—— 靠指尖反复偏心猛推盖沿把它拨起来, 不是三指捏住慢慢拧。这与 Dyn23
时代的"点按棘轮"是同一个行为病, 只是换了物理外壳。视觉上"手没在摩擦"
正是因为没有搓动, 只有间歇的推。且 4 rad/s (顶到安全夹) 远快于人手的
约 2 rad/s。

**新的头号嫌疑 (待裁定, 一次一改)**: `inertia_eff_kgm2 = 5e-3` 是真实盖
惯量 (≈7e-7, 5g/r1.7cm) 的**约 7000 倍**。这个人造重惯量让盖变成**飞轮**:
一次猛戳注入的角动量能存住并累积, 而真实盖被 drag 瞬间刹停 (τ_drag/I_real
= 0.135/7.2e-7, 停止时间远小于一个子步) —— 也就是说, **重惯量本身就是
"戳转能成功"的原因**, 真实盖只有持续握持才拧得动。
重惯量当初是 U40 为了让 τ = I·Δω/dt 可读才引入的, 与真实性直接冲突。

从 Δω 反推), 使"戳转"失效、"握拧"成为唯一通路。
