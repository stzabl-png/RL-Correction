0. 一句话

从三类逐帧 Prior(接触区间、手/物轨迹、可信度)自动编译出一条 「里程碑链(稀疏奖励,高可信锚帧)+ 模仿走廊(稠密奖励,可信度加权)」, 训练顺序、奖励结构、成功判据全部由数据推理而得;人工只做校准审批(P5),不做设计。

原则映射:锚帧=高可信帧(P4 两端锚定);操作段不模仿位姿(P2 交互帧最不可信 + P3 盖旋转不可观测,rotation_usable=false 实测);所有目标量用相对位姿表达 (接触胶水原则:手↔物相对关系是视频最可信量,绝对坐标不可信)。

2. 事件抽取与角色分派(任务文法)

2.1 嵌套区间规则

对每只手取最长接触区间(碎段按 min_len=3, max_gap=4 合并/丢弃;27 号 auto 版 左手有 [116,118] 三帧碎段,正是要被过滤的对象):

一只手的接触区间包含另一只手的 ⟹ 外层手 = holder(稳瓶手),内层手 = operator(拧盖手)。

物理解释:稳瓶手必须先于拧盖手接触、后于拧盖手离开——嵌套不是巧合,是任务语义的时间投影。

实证(全部 5 条有 contact_auto 的 clip,5/5 通过):

2.3 自动事件 vs 人工真值:实测偏差(18 号,2026-08-13)

事件 自动 真值 偏差 根因
hold_on 3 8(碰)/13(稳) 早 5~10 帧 2D 邻接在真接触前就触发
op_on 29 48(三指捏稳) 早 19 帧 present 段(15-45)holder 转瓶把盖送近右手,邻接≠接触
op_off 61 85(放盖) 早 24 帧 重建单物体=瓶;盖脱离后无跟踪,右手携盖期间与瓶无邻接

推论(写进抽取器设计): 1. 邻接区间起点不能直接当接触帧——一律做 onset 精化:邻接分持续过阈 + 手↔物相对速度归零(抓稳的运动学定义),精化规则在 18 真值上标定、0/1/4 上盲测; 2. 盖脱离之后的事件(放盖/瓶回位)对 mask 邻接链路不可见——自动化欠账 记账(两部件跟踪 or VLM 事件标注);sim 侧不受影响(仿真里盖位姿精确已知, 里程碑谓词全部可判),只是新 clip 的自动抽取暂缺这两个事件的视频证据; 3. 锚点搜索窗一律挂在精化后的事件上;±15 帧窗吸收不了 19/24 帧级的系统偏差。

免手版 onset 判据(2026-08-13 实测,与手轨迹判据并存;更省事且不受腕字段影响): 物体开始运动 = 被抓稳的运动学证据。18 号物体 3 帧位移的静止基线 0.15cm, 阈值取 max(0.8cm, 3×基线) ⟹ 运动起始 帧 14,真值 13,差 1 帧 (对比 mask 邻接给的 3,差 10 帧)。该判据只用物体轨迹,不依赖手,且自带 "抓稳"语义(碰到但没抓稳时物体不动)。 局限:①只对 holder 有效(operator 抓的是盖,重建里没有独立跟踪 ⟹ op_on 仍缺 自动来源,记欠账:两部件跟踪 or VLM);②纯旋转不可见 —— 18 尾段 return 回转 (86-100)在位移轨迹上完全没有信号(最后运动帧 73 vs 真值 100),因为绕轴转动 质心不动且 conf_rot=0,与 P3 一致。

2.2 事件序列 → 任务文法(2026-08-13 按 18 号人工真值修订)

18 号逐帧真值(用户标注,存 data/screw18_gt.json,只供测试/校准读,训练代码禁读) 把文法从四段扩成了完整闭环:

站姿 K0 ──▶ holder接近 ──▶ [8]碰瓶 [13]抓稳 ──▶ (present: holder 转瓶~90°送盖,15-45)
 ──▶ [48]op 三指捏稳盖 ──▶ 拧~180°(49-53) ──▶ 轴向拔出(54-58) [58]盖脱离
 ──▶ (并行: op 携盖放桌 [85] ∥ holder 回转~90° 86-100) ──▶ [100]瓶竖直回原位 ──▶ 终态

里程碑只挂任务语义事件(抓稳/捏稳/盖脱离/盖落桌/瓶回位); present/return(转瓶送盖、回转)是人的解法(手腕工效学),不设里程碑、 不强模仿——只以低权重走廊形式存在,策略可以保持瓶竖直让 op 从上方接近 (锚点都参照盖系,相对参数化天然兼容两种解)。

拧的真实幅度 = ~180° + 轴向拔出,无重捏(用户实标)。CAD 装配态默认两圈 (720°)才脱离,与视频语义不符 ⟹ 世界构造参数修订:装配态初始 screw_angle 设在"剩余约半圈"处,拧 ~180° 走完行程即脱离,随后盖变自由体、轴向拔离瓶口 (新增 K_pull 谓词:盖沿瓶轴离口 ≥3cm)。此为第一层世界构造决定(必须准), 依据是人工真值,不是自动先验。

3. KeyFrame 选择(稀疏锚,高可信帧)

3.1 选帧规则

逐帧综合可信度:c(h,t) = conf_pos(t)/100 × (1 − occ(h,t))(手审计落地后再乘手部档位)。

锚 搜索窗 选帧 存什么(全部相对量)
K0 站姿 — 约定(非视频) 对称待命站姿(stance_prefix 沿用)
KA_hold 接近锚 [hold_on−15, hold_on] argmax c(holder,t) holder 腕/掌相对物体系位姿 + 指尖质心
KG_hold 抓握锚 [hold_on, hold_on+10] 内接触分达该区间 P75 的首帧 — 同上 + 参与指集合(接触蒸馏交付后细化)
KA_op 接近锚 [op_on−15, op_on] argmax c(op,t) operator 腕相对盖系位姿(盖轴+盖顶面参数化,见 §3.2)
KG_op 捏合锚 [op_on, op_on+10] 同上规则 — 同上
KR_op 脱离锚 [cap_sep, cap_sep+15] argmax c(op,t) 盖脱离语义(sim=行程到顶+轴向离口≥3cm)+ 拔出方向
K_place 放盖锚 [cap_place−8, cap_place+5] argmax c(op,t) 盖静置桌面(sim 谓词);18 真值=85,视频侧暂靠 gt(§2.3 欠账)
K_end 终态锚 [hold_replace−5, 末帧] argmax c 瓶竖直回原位 XY±容差;18 真值=100

18 号各窗逐帧 conf_pos 预览(pose_audit 实测):KA_hold 窗 85~91(零遮挡)、 KG_hold 窗 80~85、KA_op 窗 74~82、拧+拔段 74~80、放盖窗 85~89、终态窗 85~86 ——每个锚窗里都有 ≥74 的帧可选,稀疏锚方案的原料充足; 最深的谷(52,帧 65~67)落在 KR 窗内部,argmax 自动绕开。

容差随锚点可信度缩放:tol = tol0 × (1 + k·(1−c*))(c* 为锚帧综合可信度; 低可信锚给松容差,而不是给错目标——P5 的工程化)。

KA_op 就是用户点名的那个关键帧:holder 抓稳后,鼓励 operator 走向 "视频里 operator 开始接触时它相对盖的位姿"。

3.2 相对量的参数化(CAD 替身兼容)

⚠ 本节已被 §11.2 约束一收紧:物体朝向不可用(18 号 conf_rot 全程 0,实测 指尖到"盖端"距离恒 ≥9cm 就是这么来的)。锚点参照系因此定义为 原点=物体质心(可信)/ z 轴=重力(可信)/ 方位角=不可观测,不进锚点; 盖相对瓶口的精确几何由 CAD 替身在 sim 侧提供,视频只负责判"哪一端是盖"。 替身入场仍走 recon→CAD 对位(recon_pose 静态重建先例)。 operator 锚按 (轴向高度, 径向距离, 相对重力轴倾角) 参数化,盖径差异被径向坐标吸收。

4. 稠密信号分配(可信度门控)

按 18 号真值分段(帧号为人工标注值):

段 帧 稠密信号 依据
接近走廊(K0→8、13→48) 0-8 / 13-48 holder/op 手轨迹模仿,逐帧权 w(t) ∝ c(h,t)。实测该段 conf_pos 74~91、遮挡 0~0.2 = 稠密奖励的主场 P4
present 转瓶(holder) 15-45 低权走廊,无里程碑。人的解法(转 90° 把盖送到右手边)是工效学产物,不是任务要求 参考角色转移(§2.18)
捏合+拧+拔(操作段) 48-58 零位姿模仿。sim 内生:垫↔affordance 环带距离、三指接触保持、screw_angle 进度、轴向拔出距离 P2 遮挡 + P3 转角视频不可观测

物体轨迹项 全程 仅 conf_pos 高的帧参与;18 号 conf_rot 全程 0 ⟹ 物体姿态项完全不进奖励,只用位置 P3

盖转角:视频不可观测 ≠ sim 里没有。 重建对"盖转了多少度"贡献为零 (对称盖,18 号 conf_rot 全程 0)——但 CAD 替身场景里这个量精确已知: 解析螺旋关节 角度↔上升 = 3.18mm/圈,env 已暴露 screw_angle/screw_engaged/screw_has_depth(带死区+去回注防漂)。 所以操作段的稠密监督不缺,只是换来源:视频给两端锚点与节奏,螺旋关节给过程真值。 ⚠ 行程按真值改:默认两圈(720°/6.36mm)是场景实现的出厂设定,18 号人实拧 ~180° 即脱离 ⟹ 装配态初始角设在"剩余半圈",否则 RL 要学的动作量是人的 4 倍, 时间轴先验也对不上。

悬空拧的处理:人把瓶拎离桌面(audit 自动检出 41 帧 lifted)横着拧;该段是低可信 操作段 ⟹ 不模仿姿态,策略可选立桌解或空中解。成功判据全部定义在相对量 (盖↔瓶相对转角、盖↔瓶口轴向距离),与瓶在桌上/手中无关。不强模仿,也不禁止。

5. 奖励编译与门控链

  • 稀疏:每个锚一个里程碑奖,回合内一次性,谓词=相对位姿进容差(KG 类另加接触谓词)。
  • 顺序门控 = grasp_first 的泛化:里程碑按事件序排链,gate_i = slowEMA(milestone_i) ≥ 0.8 才放行 i+1 的探索学分。§2.14 的教训(共享网络起步竞速必死,顺序门控 6/6 存活)直接继承, 只是"抓→飞"两级链变成由事件图生成的 N 级链。
  • 成功判据(自动派生,按 18 真值三级课程): C1 微拧 = holder 持稳 ∧ screw_angle 跟进 ≥25°(判据机制沿用旧 §2.21:跟进/失败线); C2 拧脱 = 行程到顶(初始留半圈,~180° 即到)∧ 盖轴向离口 ≥3cm(K_pull); C3 全流程 = C2 ∧ 盖静置桌面(K_place)∧ 瓶竖直回原位 XY±3cm(K_end)。 逐级毕业逐级解锁,均为 sim 内谓词(仿真里盖/瓶位姿精确已知)。

11. keyframes.py 抽取器实施方案(2026-08-13 制定)

11.0 KeyFrame 的定义(用户口径)

KeyFrame = 由 Video Prior 推理出的、且本身足够可信的关键帧; 关键帧之间可以再插入若干高可信的过渡帧。

于是参考不再是"逐帧模仿一整条轨迹",而是一串被挑选过的可信路点: 语义锚(任务事件)+ 过渡锚(高可信、且形状上必要)。没被选中的帧不产生任何监督 —— 不可信的帧不是降权,是不参与(P4 的严格版)。

11.1 已验证可用的信号(全部在 18 号上实测)

信号 用途 实测
嵌套接触区间 holder/operator 角色分派 5/5 正确(含 27 手性相反)
物体运动起始 holder 抓稳帧 帧 14 vs 真值 13(差 1);mask 邻接给 3(差 10)
掌心在物体系中的静默 刚体耦合验证 可用,但只在物体运动时可观测(静止时手物皆不动,判据无信息)⟹ 必须与"物体在动"联合

11.2 两条硬约束(实测得出,直接决定数据结构)

约束一:物体朝向不可用 ⟹ 锚点只能挂在"重力对齐"的物体系上。 实测:指尖到"瓶盖那一端"的距离全程 ≥9cm(捏稳时应 ~2cm)。根因不是手也不是质心 (两者投影都准),而是物体旋转(18 号 conf_rot 全程 0)—— 任何依赖朝向的几何量 (盖端位置、瓶轴方向)都被污染。 ⟹ 锚点参照系定义为:原点=物体质心(可信),z 轴=重力(可信),方位角(绕 z)声明为 不可观测、不进锚点。盖在瓶上的精确位置由 CAD 替身在 sim 侧给出,视频只负责 "哪一端是盖"(第 0 帧静置时世界 z 更高的那端)。这是 P3"不可观测自由度事先声明" 的第二次实战。

约束二:operator 的捏合帧目前无可靠自动来源。 三个候选信号在 18 上都不干净:mask 邻接早 19 帧;手指开口(拇↔食/中)在捏合处 5.9cm、真正收拢到 4.0cm 要等到帧 54;指尖↔盖端距离被约束一污染。 ⟹ 本轮 operator 事件用人工真值(data/screw18_gt.json),并显式记为自动化欠账; 下一轮按优先级试:①2D 口径(指尖投影 ↔ 盖在图像中的位置,绕开 3D 朝向问题); ②盖单独跟踪(两部件);③VLM 事件标注。

11.3 处理链(每一步都可单独证伪)

load ─▶ roles ─▶ events(onset 精化) ─▶ confidence ─▶ keyframes ─▶ transitions ─▶ express ─▶ emit
                                                                        └─▶ calib(HTML 校准页)
  1. load:clip → 帧号、contact_auto、物体位姿(相机系+世界系)、ARKit 关节、 逐帧 conf_pos/occl、相机内外参。一切相对量在相机系里算(投影已验证准, 且与世界系对齐无关)。
  2. roles:最长接触区间的嵌套判定 → holder / operator;不嵌套则标 unsupported,不硬套。
  3. events:每个事件带 {frame, method, confidence} 三元组,方法优先级: object_motion_onset > rigid_coupling_quiet(需物体在动)> adjacency_raw > manual_gt。 来源必须写进产物,人工来源在校准页上高亮 —— 通用性判据要能一眼查出哪几处还靠人。
  4. confidence:c(t) = conf_pos(t)/100 × (1 − occl(t)) × hand_ok(t)。 锚点是"手相对物体"的量,所以两边都要可信才算数。
  5. keyframes:每个事件在其搜索窗内取 argmax c(t);并要求 c* ≥ c_min(默认 0.5), 达不到就不发这个锚(宁缺毋假),在产物里标 dropped。
  6. transitions(用户点名的"高可信过渡帧"):在相邻两个锚之间做 可信度门控的 Douglas–Peucker:只有 c(t) ≥ c_min 的帧有资格当断点; 在有资格的帧里取"离两端连线偏差最大"的那个,递归到偏差 < tol_path(默认 2cm)。 直线段自动一个点都不出,拐弯处自动加密 —— 路点数量由轨迹形状决定,不是手调的。
  7. express:每个锚/过渡帧存 {t, kind, c, 掌心与指尖在重力对齐物体系中的位置, 手腕朝向(相对重力+接近方向), tol}; tol = tol0 × (1 + k(1−c)) —— 低可信锚给松容差,不给错目标。
  8. emit:keyframes.json(schema 见下)+ --calib 出校准页。
