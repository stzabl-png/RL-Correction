# Approach 段设计: 从初始位置接近 GraspPose

**状态**: 2026-08-16 与用户共同裁定, 实现中。
**范围**: **只学接近**——从对称待命站姿走到 GraspPose, 不抓、不抬。
判据干净、失败原因唯一, 是后续"抓稳/抬升/搬运"的地基。

**底线(用户定)**: **抓稳之前不许撞桌、不许撞物体。**

---

## 1. 为什么不用人手轨迹当接近参考

原方案是拿人手轨迹当接近段参考 + 沿轨迹做 RSI 随机起点。实测三条 clip
(`tasks/pregrasp/diag_ref_vs_prior.py`, 2026-08-16):

| clip | 交互帧腕座位差 | 朝向差 | 该 clip 训练结果 |
|---|---|---|---|
| Pour17_bottle | 6.09 cm | 25.2° | 0% |
| Pour17_cup | 6.97 cm | 30.1° | 0% |
| **Grasp3 (冠军)** | **9.61 cm** | **43.0°** | **99.99%** |

**四条实测结论**:

1. **人手轨迹走完全程也到不了 GraspPose。** 相位切换判据是 `<3cm & <15°`,
   而三条 clip 的终点差 6~10cm / 25~43° —— **两项都超一倍**。最后这一段永远得策略自己补。
2. **差距大小与成败无关。** 冠军 clip 的缺口是三条里**最大**的(9.61cm/43.0°)却训到 99.99%,
   两条倒水的缺口更小却全 0。⟹ "接近参考的贴合度"不是主要因素, 这条假设排除。
3. **形状不可信。** Grasp3 的人手在第 65~78 帧**倒退 8cm**远离 GraspPose 才拐回来;
   朝向差全程在 30~52° 晃, 从不收敛。
4. **臂会刮桌。** 人手轨迹上 **右臂外壳最低 −1.76cm(穿桌)**、左臂 −0.12cm
   (`view_pour_ref.py --mode ref --measure`)。手部连杆一直 ≥2cm 安全, 所以**肉眼看不出来**
   —— 撞的是上臂 l1~l6, 只有外壳口径量得到(l5/l6 截面半径 4~6.7cm)。

根因: 人是从斜上方**俯冲**下去抓的(瓶子入射仰角 +17.2°), 人的肩肘允许, DexMate 的臂不允许。
而且这个入射角**逐 clip 乱跳**: 瓶 −17.2° vs Grasp3 +62.6°, 差 80°, 没有可复用规律。

**⚠ 但人手轨迹不是没用, 只是用在别处** —— 见 §5。

## 2. 退避族: 起点由几何构造, 不由录像给

**RSI 需要的是"一族有难度序的起始状态", 不是"一条人手轨迹"。** 这两者可以脱钩。

```
û = normalize( GraspPose 手座位置 − 物体中心 )        ← "radial 轴"
起点族  q(d) = IK( gp + d·û , 抓姿朝向 R_g ),  d ∈ [0, D]
课程    d 的上界从 0 退火到 D  (等价于原 approach_t0_max, 但起点合法有保证)
```

三条性质正是我们要的:

1. **难度天然有序**: d 就是课程参数。d=0 是"直接抓", d=D 是"从头做"。
2. **构造上无碰撞**: 沿"物体→手"的连线往外走, 到物体的距离与 d **严格 1:1**。
3. **保证有解**: 把退避过程倒放就是一条可行路径 ⟹ **任务永远可解**。
   人手轨迹给不了这个 —— 左手在第 64 帧就压在杯子上(0.13cm), 而它的交互帧是 105,
   **从那里起步的回合一开始就在违规状态**。

### 轴的选择 (实测三选一)

`tasks/pregrasp/diag_retract.py`, 瓶子, d 从 0 退到 30cm:

| 轴 | 臂外壳→桌 | 手→物体 | 判定 |
|---|---|---|---|
| human (人手入射反向) | 10.75 → **2.19** (一路**下降**) | 单调 | ⛔ 退避时朝桌面去 |
| **radial** | 10.75 → **21.94** (上升) | **严格单调** | ✅ |
| palm (掌心法向) | 10.75 → 17.77 | **非单调**: 2.03→1.41→**1.26**→1.56 | ⛔ 退 6cm 间隙原地不动 |

palm 轴在 Grasp3 上同样失效(d=0~6cm 手-物间隙恒 6.94cm 不涨), **两条 clip 都这样, 不是偶然**。
IK: 三个轴全程可达, 位置误差 ≤0.35cm。

**radial 逐 clip 稳定**: 瓶 +21.2° / 杯 +12.5° / Grasp3 +22.2° —— 因为它由
"桌上有物体、手要抓它"这个几何决定, 而这个几何在同类任务里稳定。

### 成立条件 (用户指出, 必须做成准入门)

不变量只有一条: **沿 û 退避时到物体的距离严格增加**, 等价于 `û · r̂ > 0`。
⟹ **手座必须在物体中心上方**; 若在下方(从底下掏/物体很高而手从侧下方抓), radial 会往桌里钻。

自由度比"必须用 radial"大: 任何与 r̂ 夹角 <90° 的方向都满足不变量, 所以可以抬:

```
û = normalize( r̂ + λ·ẑ )      λ ≥ 0     ← λ 是安全余量旋钮
```

**准入门的判据不许用代理量**(仰角 >0 之类)。2026-08-16 我在零位校准那件事上被代理量
连骗三次(见 DESIGN_LOOP §2.24), 判据必须直接判它要保证的东西:

```
跑 diag_retract 扫整族, 要求
  臂外壳→桌面   单调不降 且 全程 ≥ arm_shell_margin
  手→物体       单调不降
不满足 ⟹ 抬 λ 重试; 抬到上限仍不满足 ⟹ 该 GraspPose 候选不适合接近段, 换候选
```

## 3. 站姿 → 退避起点 的前缀

**⚠ 不能用关节空间线性插值。** 实测: 关节空间走直线, 末端在笛卡尔空间**中间下沉**——

| 路径 | 手连杆→桌面 最低 |
|---|---|
| 站姿→GraspPose 直插 | **0.42 cm** (第 28/60 帧) |
| 站姿→退避起点 直插 (retract 模式现状) | **1.42 cm** (第 26/120 帧) |

两条的起点终点都安全(15.5cm / 3.3cm), **只有中段掉下去** —— 这是关节空间插值的固有毛病,
不是"直奔物体"这条路线的性质。

**待定**: 三段式(先抬升→再平移→再下降) 或 cuRobo 离线规划一次缓存。
判据同上: 外壳口径全程 ≥ margin。

## 4. 硬约束 / 软约束分层

底线要落在**两层**, 不能都塞进 reward:

| 层 | 放什么 | 为什么 |
|---|---|---|
| **硬约束(起点生成)** | 退避族按 §2 构造 | 每个回合从合法状态开始, 且存在可行解 |
| **软约束(reward+终止)** | 臂外壳→桌 / 手→非目标物 间隙罚 + 穿透即终止 | 管住策略中途乱走 |

现有代码已有的:
* `arm_table_pen` —— **已经是外壳口径**(`cfg.arm_table_shell` 开时走 `shell_pts`), 权重
  `w_arm_table=20.0`, 余量 `arm_shell_margin=0.01`。
* `terms["align"]` —— 对齐势差分(`w_align=6.0`, `cap_align=0.02`)。
* `terms["arrive"]` —— 切进抓取相位的一次性里程碑(`r_arrive=3.0`)。
* `arm_gap` 诊断 —— 有 shell 时是外壳口径。

⚠ **`arm_table_shell` 目前只在 Pour17 的 clip 注册表里开着**, Grasp3 没开 ⟹
它的 `diag/arm_table_gap_cm` 是**手部原点口径**, 一直显示 5.5~6.5cm, **看不见臂在刮桌**。
Approach 任务必须对所有 clip 打开外壳口径。

## 5. 人手轨迹保留的用途 (不可替代)

| 用途 | 为什么不能丢 |
|---|---|
| **物体 XY** (物体听手) | 消除手↔物 10cm+ 系统偏差的唯一手段, 整个摆放建在它上面 |
| **接近方位角** (Gate 1 的 yaw) | 定物体转多少度 → 定 GraspPose 朝哪边 → **radial 轴的方向就是从这来的** |
| **交互开始帧 gs** | 物体运动起始, 定相位时序 |
| **抓握之后的整段** | 搬运/倾倒全部来自人手轨迹; 本设计只替换**接近段** |

**分工**: 人手轨迹负责**去哪儿、从哪一侧**; 几何负责**怎么走过去**。
视频里可信的部分全保留, 不可信的(重建噪声最大的腕轨迹形状)换成有构造保证的几何。

## 6. 摆放约定 (2026-08-16 用户裁定, 已实现)

**顺序**是有意义的, 三步必须按序:

```
① 定姿态: canon_rot ∘ 钉死 yaw     (yaw 由 Gate 1 按视频定, 不靠 IK 搜)
② 定 XY : 用**①旋转之后**的 affordance 偏移做物体听手
③ 定 Z  : ①姿态下物体最低点贴桌 +2mm
```

原实现是 ②→①→③: builder 用 `rest_q` 算 `a_off` 定了 XY, env 随后把姿态换成
`canon_rot∘yaw`(瓶差 113.6°, 杯 149.7°), **原点没动而抓取目标区转跑了** ——
瓶错位 3.83cm / 杯 1.46cm, 正好把"物体听手"要消除的系统差装回去一部分。

修法(`env.py::_load_grasp_prior`): 姿态定案后按不变量 `物体原点 + a_off = 手锚点` 重解 XY:
```
op_new[:2] = op_old[:2] + a_off(rest_q)[:2] − a_off(canon_rot∘yaw)[:2]
```
于是 `afford_world` 仍落在手锚点上 ⟹ builder 的 `pregrasp_align` 悬停点不受影响。

**实测(三条 clip 全跑过)**: 修正量 瓶 3.82cm / 杯 1.46cm / Grasp3 1.36cm;
冠军 clip 指垫接触 4.88 → **4.62**(仍 ≥4 判据线, 未改坏)。

⚠ **顺序修正不改变指垫接触数**, 这是结构性的: GraspPose 相对物体定义, 物体 XY 移动时
抓握腕位的 IK 目标同量移动 ⟹ **手↔物相对几何不变**。倒水先验抓不住是**候选本身**的问题
(瓶 3.25 垫 / 杯 0.00 垫, 判据要 ≥4), 与摆放无关。

## 7. 用词更正 (以后不要再混)

`wrist_pos_w` / `_grasp_pos_w` 量的是 **`<side>_hand_C_MC` 这个 body 的原点**, 它在
**指垫后方 12.5~15.7cm**(实测该手从安装座到各指垫: 拇指 12.50 / 食 15.08 / 中 15.71 /
无名 15.68 / 小 15.74 cm)。它**不是腕关节**, 更不是指尖 —— 是手部安装法兰。

⟹ "腕→物体中心 13.5cm" 读起来像"手离物体很远", 实际**指垫正压在物体上**。
受影响最大的一处: 手指门控的自标定基准 `_fgate_dg` 量的正是这个距离, 日志里写成
"GraspPose 处腕-物体距离" 会误导判读(倍数关系不受影响)。
