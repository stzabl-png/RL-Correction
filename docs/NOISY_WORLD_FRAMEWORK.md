# Noisy 信息世界框架

**日期** 2026-08-09 　**作者** 杨泓 　**状态** 总纲，随各组件推进更新

---

## 一句话

**从一条人手操作视频，自动提取全部可提取的 Prior，拼装成一个 noisy 但信息丰富的仿真世界；
RL 在这个世界里探索，最终复刻出视频里的任务。**

项目开始时这个世界里只有三样东西：重建物体、重建人手、以及它们的轨迹。
本框架把它扩充成一个分层的世界，并明确每一层的误差该由谁负责。

```
                 ┌─────────────────────────────────────────────┐
   一条视频 ──▶  │  第一层 世界构造   (必须准, RL 修不了)        │
                 │  第二层 监督信号   (noisy, RL 容忍+补全)      │
                 │  第三层 元信息     (告诉 RL 该信监督几分)      │
                 │  任务层 成功判据   (VLM 对拍原视频)           │
                 └─────────────────────────────────────────────┘
                                    │
                              RL 探索/修正
                                    │
                          复刻任务的 sim 轨迹数据
```

---

## 核心设计原则（全部有实测依据）

**P1 误差分层处理。** 世界构造的误差 RL 修不了（桌面高 2cm = 策略学的是另一个世界的解），
只能做准；监督信号的误差 RL 能找补，标上可信度即可；元信息本身不进世界。

**P2 最不可靠的帧恰好是交互帧。** 实测交互段遮挡率 25~50%，位姿判别力在那里最弱 ——
而那正是 RL 必须动作的时刻。所以误差容忍不是补丁，是方案的核心约束：
不可能靠"把位姿修准"绕过去，不可靠和有用是同一段时间。

**P3 区分「不可信」与「不可观测」。** 不可信是逐帧的临时状态（这帧被挡住了）；
不可观测是物体的永久属性（瓶子绕轴自转，任何轮廓方法都看不见，实测可观测性 0.020）。
前者随帧给可信度，后者事先声明、该自由度永久交给 RL 探索。

**P4 两端锚定、中间放开。** 「低可信不奖不罚」会让那一段完全没有信号。
补救：高可信帧（抓取前/放下后，恰好无遮挡）当路径端点约束，低可信段（操作过程）
夹在两端之间自由探索。这个结构与物理过程天然吻合。

**P5 可信度标错比没有可信度更糟。** 没有时 RL 一视同仁；标错时它会认真模仿一段垃圾。
所以每个判据上线前必须过一次人眼校准（已建立 calib sheet 流程）。

| 物体网格 | SAM3D 重建 | 可用但尺度系统性偏：**拟合尺度中位 0.95，范围 0.65~1.6**（33 条实测） | **杜邦**：修 SAM3D 大小估计 |
| 网格（不可重建物体） | **资产库 CAD 替身** | VLM 读视频判定"会分离/articulated" → 自动从资产库检索。Screw27 的瓶身+盖 CAD 替身是手工先例 | **开朗**：资产库建设 |

| 支撑面高度 | 迭代估计（只用真静置帧） | ✅ 已验证。教训：直接取中位会混入"提起端着"段，实测偏 1.9cm | 完成 |

## 第二层：监督信号 —— noisy，RL 容忍 + 补全

| 信号 | 来源 | 实测质量 | 已知缺陷 | 负责 |
|---|---|---|---|---|

| 物体轨迹·平移 | FoundationPose | 干净帧 conf_pos 99 | 遮挡段判别力衰减 | **开朗**：FP 轨迹效果探究；**杨泓**：可信度分析 |

## 第三层：元信息 —— 调节第二层的权重

| 元信息 | 算法 | 成本 | 状态 |
|---|---|---|---|
| 逐帧可信度 conf_pos/conf_rot (0~100) | `pose_audit.py`：d_cent_norm 主判据 + explained 辅助 + 遮挡封顶 + 尺度封顶 | 33 条 4 分钟 | ✅ 已跑通，部分人眼校准 |
| 遮挡率 | 投影 ∩ 手 mask | 免费 | ✅ |
| 旋转可观测性 | 网格绕轴转 30° 看轮廓 IoU 变化 | 每网格一次 | ✅ 苹果 0.049 / 瓶轴 0.020 / 手机 0.281 |
| 静止段自检 | 无接触帧段必静止 → 任何轨迹源的漂移有真值 | 免费 | ✅ 判定了 FP 旋转不可信（CT≤2.2° vs FP 62°） |
| 接触置信 | per_frame overlap 数值 | 免费 | ✅ 在 contact_auto.json 里 |

**判据演化教训**（写进代码注释防走回头路）：
「静置该直立」→ 950 假阳性（手机本来就躺着）；「离稳定姿态距离」→ 漏报（瓶子横躺也合法）；
IoU 判坏帧 → 被遮挡污染（modal mask vs amodal 投影）。**物理可行 ≠ 正确；图像证据才能定姿态对错。**

## 任务层：成功判据（Success Tracker）

**方案**：把 RL 的 eval 视频 + 仿真参数交给 VLM，与原视频对拍，判断"做的事是否相同"。
对应 `steps/step5_success_tracker/`（原规划里"唯一尚未设计"的 Part，现在有了明确路线）。

**VLM 能力边界（已实测标定）**：

| VLM 可信 | VLM 不可信 |
|---|---|
| 有无自转、方向、大致圈数（苹果凭空转 98° 一票否决） | 小幅度量（4cm 抬升判成"没抬"） |
| 部件级事件（盖被拧下来了） | 左右手（散文 10/10 全错；schema+enum 10/10 对，n=1 待复验） |
| 交互定性结构 | 精确时刻 |

**使用纪律**：结构化 schema + enum + description，关思维链，强制说依据；
每改一次 prompt 全字段回归（实测加一个无关问题能把别的字段带翻）；
temperature=0 的稳定 ≠ 正确。服务：UCB GPU7 Qwen3.5-27B，`~/bin/vlm_ask.py`。

## 单条视频的流水线（目标形态）

```
video.mp4
  ├─ Step1 感知     物体/双手 mask (v17A tracking 语义) + 接触区间 + 接触点蒸馏
  ├─ Step2 重建     mesh(SAM3D | 资产库路由←VLM) + 尺度修正←杜邦 + FP 轨迹 + 手轨迹
  │                 └─ 元信息: 逐帧可信度 + 遮挡率 + 可观测性 + 静止段自检
  ├─ Step3 抓取     GraspPose 模板自动选取←杨泓 + PhysX 验证
  ├─ Step4 RL       世界构造(第一层) + 监督(第二层)×可信度(第三层)
  │                 高可信=纳入 reward, 低可信=不奖不罚, 不可观测=自由探索
  │                 两端锚定、中间放开
  └─ Step5 判定     VLM 对拍原视频 → D_verified
```

## 当前最大的三个缺口

1. **手轨迹从未审计** —— 残差策略每步跟踪它，已知腕误差 ~20cm 量级，却没有任何逐帧质量信号被使用。
2. **接触点自动蒸馏链路** —— 方法已验证（Screw27），但只有人工做的一条。
3. **可信度 → reward 的接线** —— `traj_after_contact` 折扣已存在（代码自己承认"接触后逐帧钉着噪声参考走没有依据"），把这个常数换成逐帧可信度序列即是最小实现。
